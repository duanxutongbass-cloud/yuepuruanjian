# 曲谱库·重奏乐谱整理工具 Windows V1 — Codex 可执行产品规格

**状态：用户已确认编号为全局统一流水；本文件是开发基准稿，以下业务规则为已确认要求。**

**主 App 附属软件扩展（2026-10-15，用户明确要求继续第 4 项）**：在既有离线整理器内增加可选“团队发布”，管理员通过独立 HTTPS 服务上传已入库的独立分谱，逐份明确成员、预览并确认；沿用现有编号/分类/双目录哈希，不修改原件和归档记录。不自动拆谱、不上传个人批注、不自动更改旧授权。此扩展覆盖下文 V1 的“联网/NAS/登录不做”限制，仅限发布入口；离线整理继续独立使用。协议和验收见主项目 `docs/TEAM_PUBLISHING_0101.md`。

## 0. 目标 / 非目标

**目标**：批量导入重奏 PDF → 解析文件名里的编号 → 不确定部分人工补录 → 同曲归组、疑似同曲及版本预警 → 校对逐曲表格 → 分配稳定编号 → 一次导出按乐器、按曲目两套目录，建立本地可备份的曲目库。Windows 10/11 离线、易用，不要求懂编程。

**V1 不做**：OCR、读取PDF页内文本、分析五线谱、AI模型、PDF页面编辑、用户管理、联网、NAS/阿里云部署、主系统直接同步接口、花哨数据可视化。文件格式第一版只导入 PDF。

## 1. 唯一业务事实

### 1.1 初始乐器与谱类（归档规则可设置）
| 乐器编号 | 名称 |
|---|---|
| 01 | 第一小提琴 |
| 02 | 第二小提琴 |
| 03 | 中提琴 |
| 04 | 大提琴 |
| 05 | 低音提琴 |
| 06 | 钢琴 |
| 07 | 打击乐 |
| 08 | 总谱 |
| 09 | 总谱+分谱 |

#### 按编号归档规则（2026-10-10用户新增要求）
- 07仍为打击乐；08总谱、09总谱+分谱默认允许单份正式入库，只在`按乐器分类/08总谱`或`按乐器分类/09总谱+分谱`保存一份独立PDF，不生成曲目副本，不创建空曲目文件夹。仍进入正式目录及指纹索引、占全库流水，后续同曲补录沿用原编号；不绕过重复、命名、版本及覆盖检查。
- “编号归档规则”支持每个已启用乐器编号选择“按分类最少乐器数入库、双目录”或“允许单份入库、仅按乐器分类”；每个分类编号支持普通分谱最少不同乐器数1～99，默认3。保存前列出变更并明确确认、备份数据库；取消/失败不改规则。
- 总谱等单份类型不计入普通分谱完整度。混合导入时，符合单份规则的文件可先入库，不足分类最少乐器数的普通分谱保留草稿；普通分谱补齐后沿用该曲编号。曲目目录括号仅统计实际有曲目副本的不同乐器，不统计单份类型。
- 规则只影响后续入库，每份正式谱保存其入库时的副本布局；修改规则不搬动旧PDF、改旧编号或补造/删除旧副本。改名、补录、重复比较、误拆合并及清空恢复按实际保存布局验证，单份谱不存在第二份不是缺失；普通谱仍须双目录完整。旧数据库迁移将已有分谱保留为双目录，旧清空备份缺少布局字段时以双目录恢复。
- 本节优先于下文旧有“至少3种”“双目录”通用描述。仅提供上述可验证规则，不提供任意脚本、修改流水作用域或关闭安全检查。

### 1.2 自定义分类
- 分类编号固定为 **两位数字** `00`～`99`，分类名完全由用户填写。已知例子：`01 → 久石让`。
- 分类可按作曲家、作品来源、音乐风格等任意逻辑命名，例如“迪士尼”“中国风格”，**不得将分类强制建模为作曲家**。
- 允许手工维护、批量导入 CSV；可保留未来 Excel 导入扩展，但 V1 有 CSV + 界面编辑即可。
- 不同类别的编号不允许重复；编号在使用后要变更时，必须先预览受影响曲目和文件路径，核对冲突、备份，再经过明确确认；无法保证安全则禁止直接更改。

### 1.3 编号与命名（必须字节级/字符级符合）
**旧原始 PDF**：`{乐器编号:02}{分类编号:02}{曲目文字}.pdf`
- `0101天空之城.pdf` → 乐器 `01 第一小提琴`；分类 `01 久石让`；标题 `天空之城`。
- `0201天空之城主题曲.pdf` → 第二小提琴、同分类、标题 `天空之城主题曲`（不能因为标题相似就自动变成同曲）。

**新单份分谱 PDF**：`{乐器编号:02}{分类编号:02}{曲目序号:03}{标准曲名}.pdf`
- `0101001天空之城.pdf` → 第一小提琴 `01`、类别 `01`、序号 `001`。
- `0701001天空之城.pdf` → 打击乐 `07`、类别 `01`、序号 `001`。

**新曲目文件夹**：`{分类编号:02}{曲目序号:03}{标准曲名}（{乐器种数:02}）`
- 例：`01001天空之城（07）`。
- 括号为中文全角 `（ ）`；序号始终三位，不使用四位；曲目数字合法范围 `001…999`；超范围阻断并预警。
- 计数对象是该曲目**该版本中不同乐器的数量**，不是PDF份数；附加PDF不改变乐器计数。
- 标准曲名为空、输出非法 Windows 路径字符或路径冲突时必须人工修正；不要悄悄改成另一首曲目。
- **注意顺序保持一致**：旧文件名前四位是「乐器+分类」，新文件名前七位是「乐器+分类+序号」。解析顺序：先严格尝试完整新格式，再尝试旧格式；不可只盲读前四位。
- 识别新旧格式时必须验证乐器和分类编号已定义，且剩余标题非空；前缀数字歧义时弹出人工确认。

### 1.4 曲目序号：全库统一流水（用户已最终确认，不可切换）
- 全部分类**共同使用唯一的三位曲目序号池 `001…999`**；**不同分类之间也不允许重复相同序号**。不得再提供“按分类独立编号/全局编号”切换选项。
- 示例：分类 `01` 的第一首为 `01001天空之城（07）`；下一首如属于分类 `02`，序号应为 `002`，可命名 `02002示例曲目（03）`；不能再给这首曲目分配 `001`。
- 同一曲目同一版本的所有乐器分谱共用同一序号；同一作品确认第二版或其它新版本时也必须获得**新的全局序号**。
- 对导入的已有编号优先沿用；检查**跨分类**及同分类的序号冲突，冲突预警由用户处理，不能自动覆盖、更改已入库编号或强行合并。
- 2026-10-18用户更新：新曲目使用**全库真正未占用的最小编号**，以3位补零。已有编号全部保持，所有song状态（含merged历史）及本批显式编号均保留占号；如已占用`001、003、007`，下首新曲用`002`，再下一首用`004`，各分类共用同一流水。仅当`001…999`全部占用时阻断，不因已有`999`就宣告满号，不擅自扩位。预览、部分选中归档和实际提交使用同一规则；原PDF及已有目录不改名。
- 在成功归档时才正式占用序号；草稿预览只显示候选序号，取消或失败不得导致永久占号。已经正式归档、后来停用的序号也不得随意回收复用，以免与旧文件冲突。
- 数据库对正式占用/保留的 `seq` 建立**全局唯一约束 `UNIQUE(seq)`**，不能用 `UNIQUE(category_id, seq)` 代替。

### 1.5 多版本规则
- 只有一个版本的曲目：**不显示“第一版”“普通版”**，如 `01001天空之城（07）`、`0101001天空之城.pdf`。
- 第二版不是覆盖：新建独立 song_id、分配新序号，标题使用 `天空之城（第二版）`，例如（若002可用）`01002天空之城（第二版）（07）`、`0101002天空之城（第二版）.pdf`。
- 第三版为 `（第三版）`，依此类推；版本属于同一个基础作品但每个版本有独立分谱集合，按1.1的归档规则检查。
- 旧版不自动改成“（第一版）”，已归档的路径/编号保持不变。
- 文件名明显带“第二版 / 第2版 / V2”等可作为**候选提示**，仍须用户确认；不同 PDF 的哈希值不等于“确认第二版”。
- 同一作品新导入的分谱，需要由用户确认是“补到已有版本 / 新建第二版或其它版 / 替换现有分谱 / 暂存”，不可静默判断。

### 1.6 重奏与归组
- 普通重奏分谱默认至少3种不同乐器（按分类规则可调整）；不足时进入“待补齐”草稿。08/09等配置为单份入库的类型适用1.1例外，可独立正式入库。
- 用户明确选择“强制正式入库”时，普通分谱也允许仅一个声部正式入库；强制新建和强制归入已有曲目均适用。正式预览显示真实数量和全部原名→新名，须勾选确认；仅本次选中分谱入库，不自动扩展到同组其他草稿。对声部不足的正式曲目持久记录最少数量豁免与强制审计，后续补谱沿用原号；其他曲目仍遵守默认规则。目录括号、目录列表、缺谱扫描保持真实数量，缺谱为非阻断提示，目录注明“强制入库，声部待补齐”。重复、同乐器冲突、命名、源件变化、覆盖或目录安全检查不豁免，取消不占号、不写正式输出。
- 用户可主动“选中分谱转入待审查”：将明确选中的不足3种乐器、重复、同乐器多文件、命名不明确、编号/分类冲突等文件保存到输出根目录下独立的 `待审查/批次/原因/分谱记录/原始文件名.pdf`；每份保留原名、全部原因、原始路径和审查说明，批次保留文本及机器可读清单。同名文件隔离保存，不覆盖原件，不占正式序号。保存与哈希验证成功后移出草稿；待审查列表支持搜索、打开PDF、选择放回草稿并保留人工校对字段。单选只处理该份，多选只处理选中范围，不自动扩展同曲声部或全部有预警草稿；未选中时禁止默认整批转存。关联问题仍写入所选文件说明，无预警但人工指定的文件记“人工指定待审查”；同一文件多原因全部记载，一份保存副本按首个原因放置。确认清单与事务提交均校验相同选择范围，取消/失败保留原草稿。
- 同一组按“分类 + 经人工确认的标准曲名 + 版本”归档；可能同曲不同名，仅预警，不能自动合并。
- 例：`0101天空之城.pdf` 与 `0201天空之城主题曲.pdf` 要显示“疑似同曲”的对比及操作，不允许无提示合并。
- 归档后补谱：保持已有编号，增加对应分谱，并将文件夹后缀人数如 `（06）→（07）`；两套输出都同步更新。补谱不能自动混入其它版本。
- 文件名别名由用户确认后记录，供未来候选匹配；不根据别名直接覆盖已有版本。

## 2. V1 功能与界面（尽量简单）

### 2.1 主工作台三栏
- **左侧**：批次曲目列表，含曲名、乐器数、状态（待识别、待确认、待补齐、可归档、已归档）、预警计数；点击切换。
- **中间**：当前曲目的分谱表，至少含 `乐器 / 原始文件名 / 标准曲名 / 新文件名（预览） / 编号 / 状态`；支持单条修改、复选多条批量修改共同字段；可一键打开本地 PDF 阅读（不解析内容）。
- **右侧固定区域**：「预警与人工校对中心」，显示关联当前批次和曲目问题；点击预警，定位、高亮中间相关行；可选“合并同曲 / 分别保留 / 关联已有曲目 / 确认新版本 / 编辑分类或乐器 / 跳过”；修改即时重新校验。
- **底部**：导入文件/文件夹、保存草稿、预览归档方案、确认本曲目归档、下一首、批次总表。
- 界面中文，Windows 常用分辨率可调整窗口，操作明确，避免反复弹窗。
- 长曲名、源文件名、新文件名及预警详情必须有完整查看入口，不仅依赖省略文字。主表格/曲目报告/预警列按内容分配初始宽度，支持拖动列宽及横向滚动；字段提供完整悬停提示（路径等既有专用提示保留）。草稿提供“查看完整信息”，预警提供“查看预警完整详情”；所有业务表格右键可查看所选行完整内容及关联路径，长文字换行、只读可复制，隐藏行不纳入，多选可一起查看。保留紧凑行高与双击打开PDF、不改变任何解析字段/编号/文件。

### 2.2 批量导入与人工录入
#### 主界面归纳与编号管理（2026-10-10）
- 顶部菜单“文件、分谱处理、乐谱库、设置、数据管理”分类组织命令；主表下方仅保留导入下拉、打开选中PDF、校对选中分谱、确认入库和查看曲谱库，草稿占主体高度。分类、乐器、归档规则及低频/危险操作移出常驻表单和底部按钮；预警表与常用处理入口保留。主表默认列宽随窗口及视口变化，优先保留乐器/编号/状态，名称可完整提示；用户手动改宽后不自动复位，保留横向滚动与紧凑行高。
- 草稿右键提供打开、校对、明确归入指定正式曲目、对比重复、暂时无用、待审查、移除等。已选行右击保留多选，未选行右击只选该行；空白区域不执行上次选择，菜单本身不写数据。预警右键提供处理、PDF、重复对比、仅确认提示；全部表格完整信息入口保留。低频操作另有顶部菜单入口，所有原确认/备份/回退保持。
- “设置 → 乐器管理”维护两位ASCII数字编号、名称、启用状态及归档模式，确认与数据库备份后原子保存；支持新增自定义编号，后续导入/校对/规则界面立即识别，重启不丢失。新增不得覆盖已有编号；已有编号不直接改码，存在入库分谱时禁止直接改名，未入库可改名；有任何草稿引用时禁止停用，历史记录保留。名称限制Windows合法路径，保存失败回退名称/状态与模式。
- “设置 → 分类管理”独立窗口新增/编辑分类，维护分类代码身份，不用新增覆盖已有编号；编号归档规则入口移到“设置”。配置变化后刷新草稿、预警及报告；原PDF、既有编号及文件布局不动。
- “强制归入指定曲目并入库”：多选草稿→手选库内标准曲目（可搜索与打开对比）→原值/标准名、分类、编号预览并确认→重新检查→正式入库预览并勾选强制确认。只校对和入库当前选中分谱，无关或未选中草稿不改；按1.6允许一个普通声部入库并保留原正式序号。疑似曲名不自动归组，不覆盖已有同乐器分谱；重复等阻断仍列对比。取消选择/修改预览不写入，取消入库保留已确认草稿；源PDF不变，不能绕过文件安全检查。
- 草稿右键和“分谱处理”另提供“强制新建独立曲目入库”，不用先有正式曲目；复用校对窗口，默认选中此次进入窗口的全部分谱，明确“新建独立曲目（分配新编号）”，用户统一曲名/分类并逐份选乐器。校对预览确认独立身份，清除所选草稿已有目标/流水并记录原编号；实际入库按全库规则分配新号，原件/旧正式编号不改。普通校对下拉也可选新建，重开保留有效选择。
- 强制新建按1.6可仅一个普通声部入正式库，窗口按钮为“强制入库”；普通校对下拉的新建只确认独立身份，不自动豁免最少数量，08/09仍可单份。两种入口均不绕过重复、同乐器冲突或文件安全。库内同分类同名或仅空格不同不得强制误拆，应归入已有曲目或明确可区分名称；未选中的同名草稿按下条在窗口集中带入预览，多首不能不填统一名就合成一首。独立确认只对有效曲名/分类及无既有目标/序号生效，修改或切换归属清除；再次出现同名正式身份会阻断，不把新建静默改为补谱。普通新建的总谱先成功入库时，同组已确认的新建普通草稿事务内关联这次新号，后来补齐沿用；失败连同关联字段回退。强制入库不改最终未选中草稿。取消校对无修改，取消正式预览保留已确认草稿，不占正式号。
- 新建校对检测到本批其他已识别、同分类且同名/仅空白或字母大小写不同的分谱时，服务返回明确关联ID，界面将其带入当前表格并一同选中；已在窗口但未选中的关联分谱不重复加行。保留原行未保存的名称/分类/乐器与归属，更新总数和本次选中数量，再展示包含全部新增分谱的原→新修改预览，未确认不写入。新增行可打开源PDF，用户可取消、改选或区分曲名；不自动抓取仅名称相似、分类不同或版本后缀不同的分谱，不自动合并正式曲目或决定重复取舍。原始PDF变化/缺失仍阻断；预览期间新同名草稿出现则回退修改、带入当前窗口并要求重新确认，不能沿用旧确认偷偷扩大保存范围。

- 支持多选 PDF、文件夹（可选含子目录）、拖放、一次数百份；非PDF跳过并汇总。
- 合法四位旧编号或七位新编号直接解析；无效/缺失编号、未知分类、未知乐器、空标题进入待录入列表。
- 无编号文件可逐条录入；支持多选后批量设置相同分类、乐器或标题（字段由用户选）；不可批量错误覆盖不同曲目名称而不展示影响清单。
- 录入时选择已有曲目版本或新建曲目。人工录入保存草稿，下次启动保留。
- 预警中心“处理选中预警”和草稿“校对选中分谱并入库”打开同一校对窗口，支持多选相关分谱、打开源PDF、统一曲名/分类、逐份选择乐器，以及明确选择已入库目标编号/曲名。先展示全部所选分谱校对字段原值→新值，确认后原子保存草稿与操作历史；原件不重命名。指定已有目标可更正草稿解析出的旧编号并记录原值，正式库序号不变；搜索文字必须实际选定列表项，完全同名歧义目标阻断。
- 校对窗口默认仅选第一份，曲名/分类/归属与保存、入库作用范围跟随窗口内实际选择，不因同一预警关联多个不同曲目而强制一起修改。单选可分别编辑，多选/“选择全部分谱”明确进行批量校对；多曲名且未明确填写统一名称时保留各自原名。显示选择数量，修改预览只列当前选择，未选中记录和原件不变。“保存校对到草稿”成功后保持窗口，允许继续选另一份；切换选择缓存窗口内未保存字段，不自动提交，关闭后放弃尚未保存的编辑。
- 提供“查找疑似对应曲目”：只按文件名/校对曲名匹配当前草稿和正式目录，按名称相似度和分类排序，列出位置、完整名称、分类、正式/已解析编号，支持搜索全部或仅看疑似以及打开候选PDF；名称相似度不得解释为内容相同。候选必须手选，确认“归入选中曲目”只填当前选择，仍经过原值→新值预览与保存。草稿目标不能同时是本次被修改记录；明确归入草稿时复制其标准名/分类及已解析编号（旧编号变更记录原值），不修改目标或正式库，不分配流水。提交前重新核对候选记录与PDF及选择范围，变化/缺失阻断；正式目标沿用已有校对/歧义规则，后续重复、编号和不足乐器仍照常校验。候选取消或隐藏项未选定不能产生修改。
- 提供独立“统一为库内名称”，仅列正式曲目，由用户明确选定后采用库内标准曲名、分类及已有编号，再预览并确认保存当前选择；不要求手打名称，不修改目标/原件或未选中记录。回到校对窗口时仍显示有效的已确认库内归属。库内名称候选使用非阻断提示（库内名称相似阈值75，草稿间78，保留包含关系候选）；不自动判同曲或版本、不自动应用别名。有效确认须同时满足正式目标存在且同分类同名唯一、当前曲名/分类/序号与目标一致；仅对此部分分谱停止乐器后缀、已有版本和同名/相似名的重复追问，不掩盖未确认的其他分谱。目标字段变更、失效或同名歧义恢复检查。PDF重复、同乐器冲突、编号、少乐器和输出安全检查不变；报告以预警实际源文件范围归属，不能因已确认名称被另一条提示引用而显示虚假阻断。
- 校对后的入库失败在窗口内持久显示“已保存、未入库”、有效库内名称和实际阻断原因，提供可滚动的全部原因/文件名查看，不反复弹出泛化警告；名称相似等信息性提示不得列为实际阻断。即使未执行缺谱扫描，也按报告显示真实独立乐器数；可列库内候选标准名，但不强制采用。重复/同乐器冲突说明名称已解决不代表分谱取舍已解决，列出涉及文件；预览取消、编号/源/输出异常保留真实原因，不冒称取消或缺谱。长原因摘要限长并可查看完整值，不能把控件挤出窗口。
- “保存校对到草稿”明确未入库，保留一次校对修改确认；“校对并入库”及右键归入已有曲目在条件通过时，将字段原值→新值与最终原名→新名、正式编号及目标目录合成同一个最终确认窗口。预览使用事务内临时校对后回退，不保存字段、预警、审计或编号；最终确认才保存校对，再按原流程复核并归档。取消合并预览不保存本次修改，已有确认草稿不回退；条件不足或重复冲突时可确认校对保存草稿，再处理实际问题。强制声部豁免在同一个最终窗口勾选，不另弹校对确认。确认后的正式方案发生变化须阻止未预览输出并要求重新确认，不复用旧批准扩大范围；实际写入失败保留已确认校对及具体原因。成功结果显示主界面和状态栏，不弹要求关闭的成功框。只生成本次所涉曲目方案（普通操作包含同组其他草稿分谱），成功仅移除实际归档分谱；不因其他无关曲目的编号冲突阻断本组，流水仍避开全库及本批其他分谱保留编号。重复取舍、替换旧谱等安全确认不省略。
- 校对窗口右下角入库按钮旁提供箭头下拉：“普通校对并入库”“强制新建独立曲目入库”“强制归入已有曲目并入库”，无需关闭校对窗口。强制新建采用当前选中的分谱及尚未保存的名称/分类/乐器并明确独立身份；强制归入已有曲目复用已选有效正式目标，未选目标时在窗口内打开正式候选选择。选择已有曲目采用库内标准名称/分类/编号，但保留当前乐器校对。取消候选或校对预览不写入、不丢输入；取消归档保留已确认草稿并留在同一窗口，强制确认、仅所选范围和安全校验同1.6。下拉普通操作不因从强制入口打开窗口而自动豁免数量。

### 2.3 固定预警中心——触发与动作
| 预警 | 触发 | 必须动作 |
|---|---|---|
| 无/错编号 | 无法匹配合法旧/新前缀 | 人工补录或跳过 |
| 未定义分类/乐器 | 编号在字典中不存在 | 选已有/新建分类或修改 |
| 疑似同曲不同名 | 标准化后相近、候选别名、本批或已有库近似 | 对比后人工合并/保持分开/暂缓 |
| 同名不同版 | 同基础曲名但文件差异、名称含版本字样 | 指定版本或替换/补谱/跳过 |
| 同曲同乐器冲突 | 同一版本对应同一乐器多份文件 | 确认重复、替换或新版本，不静默覆盖 |
| 完全重复 | SHA-256 一致 | 提示可跳过；保留处理记录 |
| 分谱不足 | 版本组中独立乐器<3 | 保留草稿，阻止正式归档 |
| 编号/目标路径冲突 | 已被占用、Windows大小写不敏感重名等 | 解决前阻止写入 |
| 分类编号变更影响 | 修改已使用两位分类编码 | 列出影响范围、备份及二次确认 |

重复/同乐器冲突必须提供逐份文件对比清单，显示分组、问题、草稿或已入库位置、曲目/乐器、文件名和完整路径；支持搜索、打开PDF。用户确认重复的草稿应先复制并核对哈希，保存到输出根目录 `已确认重复/曲名/乐器标注-曲名（重复N）.pdf`，一首曲目一个文件夹、PDF直接存放，不创建日期批次或逐份子目录；重复序号依据已存文件和历史清单继续递增，不覆盖、不占正式流水。完全相同且库内归属明确时使用库内曲名/乐器，否则保留校对字段或原文件名作为命名依据；安全处理Windows非法字符、保留名及超长名称，同名截断冲突分开，完整原名/曲名/字段/源路径/保留对照仍保存在根部和曲目文本/JSON清单及统一说明中，成功后移出草稿。批量处理已入库相同副本只匹配SHA-256且需要用户确认；保存失败回退新增文件与说明，保留草稿、既有重复和源PDF/库内文件。重复挡住所有候选归档时直接展示该清单，不把问题概括为“缺少3种乐器”；无冲突的完整曲目可独立归档，问题曲目继续保留。已入库目录每次打开读取最新记录，按独立song_id汇总，一首曲目一行；不同编号的版本不合并；独立乐器数和分谱数分别显示，同乐器多份明确标示，可点开逐份查看；暂不直接编辑正式编号或删除库内分谱。

- 提供“整理旧重复目录”：仅扫描程序旧日期批次/旧合并目录，读取清单并核对PDF和路径，先显示曲目文件夹及旧名→新名预览。确认后保存数据库快照，复制并校验新布局，旧目录（含全部说明/对比记录）转入修改备份，保留备份定位记录；取消无写入，可捕获失败回退目录和新增输出。清单/PDF变更、缺失、越界/链接、未登记PDF或旧目录正被草稿/库引用为源文件时阻断，不猜测搬移。总清单缺失但曲目已有新清单、曲目/总清单不一致时阻断，不覆盖确认历史；不改原始PDF、草稿字段或正式库编号。

- 预警状态 `待处理 / 已处理 / 已确认无须修改`，保留操作历史；对信息改变重新计算，避免旧确认掩盖新风险。
- 不提供把“标记已处理”误当实际处理的入口；使用“处理选中预警”进行真实校对及入库，另设“仅确认提示无须修改”只记录结论，不入库也不绕过阻断。校对窗口可确认跳转重复对比处理，尚未保存的校对字段不自动应用。右侧控制区可滚动，操作入口不因小窗口被挤出。
- 字面标识“高相似”只能触发**候选提示**，不自动确认等同。可用 RapidFuzz 对规范化后的文件名进行相似度检测；阈值作为配置项，初值由测试调整；对“主题曲”等语义差异不自动抹掉。
- 重复对比清单支持复选框跨组批量确认、勾选可见草稿/取消全选，以及仅勾选SHA-256完全相同的多余副本；自动选择没有库内副本时保留最早导入的一份，不为指纹不同的文件自动决定重复或版本。批量选择显示唯一分谱份数和涉及组数，一批一次确认，不逐组弹窗；搜索后选择和确认只作用于可见勾选，明确命名的“全批已入库相同副本”操作除外。库内对比行不可勾选转存，同一分谱跨多个预警行须同步勾选并去重。用户明确人工确认的草稿即按重复转存，不要求曲名、分类、乐器或内容指纹相同，也不要求属于机器识别的重复组；允许转存全部明确选中的草稿，记录人工结论，不伪称哈希相同。校对窗口带入当前选中分谱及已知对比件，不要求退出自行查找。自动完全相同快捷处理仍校验组内保留件。所有处理均核对选中记录和源PDF、排他复制并验证哈希，成功才移出草稿；失败回退，原始PDF和库内PDF始终保留。
- 导入文件/文件夹完成后，仅针对本次新增分谱立即提示已有库内完全相同或同曲同乐器分谱；入库前（包括校对后入库）再次校验本次作用范围及同组草稿。提示列出新旧PDF、库内编号/分类/曲名/乐器和完整路径，支持打开对比；内容相同可点击专门按钮一次明确确认转入重复库，不要求先补录文件名，内容不同不预勾选、不自动判重复。库内行不能勾选；同一草稿多组去重转存。取消保留草稿、不入库；可明确选择暂缓重复而继续入库无冲突曲目，阻断不被绕过。提交前重新比较预览记录，变更阻断并刷新；复用已确认重复复制/哈希/清单流程，完全相同快捷处理另校验保留件，人工勾选按用户明确结论转存。成功后仅移除确认草稿，原件和正式库编号/PDF不变。
- 同一分类下曲名仅空白字符不同（含半角/全角空格）时，生成阻断校对预警，明确显示空格位置；同时检查本批草稿与已入库目录，未经人工处理不分配新编号。不自动合并或改动已入库编号；人工统一曲名后重新检查同乐器多文件和重复风险。
- 文件名曲名末尾包含与当前乐器配置及编号匹配的乐器标注（例如 `HANDCLAP-小提琴_1`、`HANDCLAP-中提琴`、`HANDCLAP（钢琴）`）时，仅提出去除该标注的曲名建议，不自动改解析值或合并。按同分类及精确建议曲名列一条“乐器后缀需统一曲名”阻断校对提示，包含所有关联草稿及同名无后缀草稿、原曲名和库内精确同名对照；同一候选内部不再产生两两相似提示。处理预警/多选校对时预填建议，必须确认字段原→新后才归组/入库，允许取消或人工保留真实曲名。第一/第二小提琴支持匹配的 `_1`/`_2` 等标注；编号与标注不一致、无清晰分隔、曲名中间乐器文字不自动删。不跨分类、不移除版本文字、不迭代删除多层后缀；原件/已有流水不变，校对后仍检查重复、同乐器和编号冲突。转存待审查保留“乐器后缀待确认”原因及原字段。

### 2.4 每首整理报告（归档前必看）
- 顶部：分类名称和编码、标准曲名、版本、序号（待分配/正式编号）、独立乐器数量、目标文件夹名、预警状态。
- 表格：每个PDF对应的原文件名、乐器、拟输出的新文件名、识别来源（文件名/人工）、异常与处理状态。
- 按钮：`返回修改`、`保存为草稿`、`确认本曲目并归档`。只要有阻断预警，不允许点击成功归档。
- 批次完成后可查看总表：曲目、版本、编号、乐器数、预警数、已归档/待补齐/待确认。

### 2.4.1 暂时无用乐谱
暂时无用处理模式：用户在草稿中多选分谱，预览原名→暂存名后明确确认。PDF统一直接放在输出根目录的“暂时无用乐谱”文件夹，不建立曲目/批次/分谱子目录；尽量保留原名，Windows非法字符/保留名/长名安全处理，同名以“（同名N）”区分、独占创建不覆盖。记录完整源路径、哈希、校对字段和用户选择原因于统一清单；复制校验成功才移出选中草稿，未选中记录、原始PDF和正式库不动，不要求3种乐器、不占流水、不判重复。提供搜索、打开PDF/文件夹、按保存字段核对副本后放回草稿；保存副本仍保留，同一暂存记录不重复恢复。取消不写入；可捕获失败回退新副本/清单/草稿，回退受阻明确提示，不宣布成功。此目录纳入全部清空备份及恢复。

### 2.5 已入库目录编辑
- 已入库目录提供“全部分类/自定义分类编码及名称”下拉筛选，按分类编码精确匹配，与曲名/编号搜索叠加；展示当前可见/全库正式曲目数，空分类显示0。停用分类保留查看入口，merged占号记录不作为正式曲目显示。筛选不改数据库、编号或PDF；隐藏当前行后取消选择，修改分类成功后切到新分类并选中更新曲目。
- 已入库目录选中曲目后可修改曲名及分类；正式三位序号、song_id、版本身份保持不变，不提供重新编号或自动合并。保存前必须显示两套目录所有分谱的旧名/路径→新名/路径预览，可取消。
- 分类/曲名修改须同时更新数据库、按乐器分类副本和按曲目分类副本；修改前保存数据库快照、旧PDF及操作计划到输出根目录的“修改备份”。源PDF不改动；库内文件作为原始源文件被引用时阻止修改。目标文件/目录重名、同类同名曲目、库内缺失或哈希变化、同乐器多份导致新名称冲突时阻断，不能覆盖或静默合并。
- 可捕获失败回滚文件和数据库；若回滚部分失败，明确阻断并提供备份位置，不宣布成功。成功后当前目录刷新，后续补谱匹配新分类/曲名但继续用原编号。库内历史重复清理和重新编号不属于本次曲目编辑。

### 2.6 全部清空与恢复
- 提供独立可见的“清空全部整理数据”，与“清空当前草稿”区分。确认前展示库内曲目/分谱、导入/预警记录数量、将转存的目录及备份位置；需勾选确认，不能自动执行。
- 仅清除曲目、分谱、别名、导入批次/明细、预警及操作历史；分类、乐器、输出设置保留。将输出根目录下六种程序整理目录（按乐器分类、按曲目分类、待审查、已确认重复、修改备份、暂时无用乐谱）转入同根的“清空备份/独立批次”，不删除原始PDF、不移动其他用户文件或已有清空备份。目录链接/越界或其中有现存源PDF时阻止清空；缺失源文件不妨碍把损坏库备份后清空。
- 全部清空是用户明确确认的新库开始，现有序号只保留在旧库备份，新空库从001分配；正常库编辑、普通清草稿仍不得重用已占编号。清空后所有工作列表刷新为空。
- 用SQLite一致性快照和目录转存共同提交，失败回滚。提供“恢复上次清空”，验证备份归属、清单、数据库哈希、目录及结构，并禁止覆盖新整理记录/目录；恢复前再保存数据库快照，恢复记录/配置/原目录，失败保持清空后状态及备份，部分恢复失败须阻断并给出路径。断电恢复另需验收，不以可捕获异常回滚等同于断电恢复。

### 2.7 人工确认误拆合并
- 已入库目录选中要保留编号的曲目，提供“合并误拆曲目”入口；仅允许同分类、同版本且同名或仅空白不同的两条记录，不提供任意修改流水或自动合并。用户选择另一条记录及统一曲名；保留目标song_id、原序号和版本身份，另一条标记为merged保留序号占号记录，不再显示为独立正式曲目。新曲可补其他真正空号，但不重用合并留下的编号。
- 显示全部分谱原编号、乐器、文件、SHA-256对比结果，支持打开库内PDF；同乐器必须人工选定一份保留，其余逐份确认重复并转存，未决定不能提交。指纹不同不等于重复或新版本，不默认取舍；如果是不同版本则取消。每种乐器必须保留一份且至少3种，不能借合并丢弃独立乐器。
- 勾选同版本与重复确认后，预览全部旧名→新名及两套输出目标；取消不写入。提交前保存数据库快照、旧双目录PDF和方案到“修改备份”，未保留PDF的两套副本直接转存到“已确认重复/曲名”，各自标注重复序号，保存独立合并说明/事件对比记录，不另套分谱目录且不覆盖既有说明；所有复制核对哈希后同步数据库与两套输出，成功后刷新为一条正式目录记录。保留原始PDF及审计记录，库内重复索引不再把merged记录当成正式谱。
- 原件引用、文件变化/缺失、目录未登记文件、目标冲突或记录变化阻断；复用目录编辑的事务、文件回退与备份，可捕获失败恢复原两条记录和双目录，回退不完整明确阻断。断电恢复仍须另行验证。

### 2.8 节目单打包（用户新增要求，2026-10-11）
- 顶部独立“节目单打包”入口；从正式库按曲名短词、分类名称/编号、正式流水即时筛选，可多选添加或双击添加，不自动采用相似名称。已选曲目不因筛选消失；默认按添加顺序，允许输入1～9999的唯一节目序号、上移/下移和移除，按节目序号升序打包。
- 预览全部节目与库内原文件→打包路径后一次确认。输出为独立节目文件夹，按当前乐器编号及名称分专业，PDF名为“节目序号（至少三位补零）＋空格＋库内标准曲名”；保留版本名称，不修改正式库流水、目录、数据库或源PDF。包括总谱/总谱+分谱的实际单份存档，不人为要求三种乐器；同乐器多份正式谱不自动选择，先人工解决。
- 附UTF-8节目单文本、JSON及缺谱清单；缺谱按该节目出现的乐器类型比较，只提示缺少，不伪造分谱，可确认打包已有谱。支持同时生成按专业目录组织的ZIP并校验CRC；不合并PDF页、不解析PDF内容。节目单可保存/载入，载入核对当前库曲目身份、名称、分类及原流水，失效时保留当前清单并提示重选。
- 输出位置在正式库目录之外。同名已有目录不覆盖，链接/越界拒绝；库内实际副本均核对哈希，后台暂存、复制校验、提交前重建方案，再排他创建目标目录。复制/发布失败回退本次输出，回退受阻明确定位，不冒称成功；运行期间不允许关闭任务窗口，避免后台线程被销毁。取消预览不生成输出。

## 3. 输出目录与文件安全

### 3.1 两套真实 PDF 文件（不是快捷方式）
```text
乐谱库输出/
├── 按乐器分类/
│   ├── 01第一小提琴/
│   │   └── 0101001天空之城.pdf
│   ├── 02第二小提琴/
│   │   └── 0201001天空之城.pdf
│   ├── 03中提琴/
│   ├── 04大提琴/
│   ├── 05低音提琴/
│   ├── 06钢琴/
│   ├── 07打击乐/
│   ├── 08总谱/          # 默认仅在此保存一份
│   └── 09总谱+分谱/     # 默认仅在此保存一份
└── 按曲目分类/
    └── 01001天空之城（07）/
        ├── 0101001天空之城.pdf
        ├── 0201001天空之城.pdf
        └── ...（共7种乐器时为7份）
```
- 上例目录缩写 `...` 仅用于文档，程序不得生成同名字面的省略文件。
- 普通分谱实际输出两份独立可读PDF；单份类型只保存按乐器副本；源文件从未就地变更。
- 路径含中文/空格正常；默认避免 Windows 非法字符 `<>:"/\\|?*`、保留名、尾随点空格、超长路径；出现风险应提示用户校正，而非静默丢弃信息。

### 3.2 安全提交（必须）
1. 先在内存/数据库草稿中解析、人工校对、生成**精确操作计划**（新建/改名/复制/替换）；展示覆盖风险。
2. 检测源文件仍存在、SHA-256 与初检一致、所有目标路径唯一、剩余空间合理；不允许未经确认覆盖。
3. 用输出根目录下独立暂存区复制文件，校验复制件内容一致；对已有目录更新先建立恢复点/备份及操作日志。
4. 仅在所有目标均可提交时更新双目录，并在成功核验后提交数据库“已归档”状态；如中途失败，恢复旧目录或标记未完成且可安全重试，**绝不谎报成功**。
5. 完全相同文件重复提交应具备幂等性；只记录跳过，不多次创建。
6. 默认不提供一键删除原始文件；不默认替换旧归档的 PDF。用户明确选择更好的新谱并确认同一版本时，可按下述流程替换库内分谱。备份/恢复与编号数据库及文件索引同步进行。

### 3.3 人工保留新谱、旧谱转入重复库
- 已有入库分谱对比窗口提供独立的“保留选中新谱入库，旧谱转入重复库”，与“确认勾选文件转入重复库”方向相反，不复用自动重复取舍。新谱须已识别且与库内分谱乐器一致；库内目标不唯一时用户须选定明确库内行，一份库内谱一次只能被一份新谱替换。不自动判新谱质量或版本。
- 预览原编号/曲目/乐器、新谱原名、库内旧名、全部正式目标和旧谱转存路径，支持打开新旧PDF及完整信息。必须勾选已对比、确认同一版本才提交；取消无写入。采用库内标准名称、分类、原序号、版本和历史存档布局，不改变曲目数或独立乐器数，不新增版本/流水；普通两套PDF同步更新，单份谱仍仅一套。
- 提交前重新校验预览的草稿、库记录、曲目身份、源文件哈希、旧正式副本和重复分配；链接/越界、库内文件作为源PDF被引用、缺失或变化阻断。先保存数据库快照、新谱及所有旧正式副本到“修改备份/替换分谱_批次”，校验哈希，再按现有重复布局存一份旧PDF到“已确认重复/原曲名”，记录旧来源、旧正式路径/记录、新来源/哈希及替换事件；不为双目录旧副本制造两份重复。保持既有重复清单及递增序号。
- 新谱排他写入仅预览确认的正式位置并校验，事务更新既有score的来源和哈希、审计日志，成功后只移出选中草稿。原始新旧PDF永不改动；未选中草稿不变。可捕获失败回退正式副本、重复输出/清单及数据库；回退受阻明确停止并定位备份。事务已提交后若清理失败，保留已提交新谱与记录、刷新实际状态并提示停止检查，不错误回退为与库记录不一致的旧谱。断电恢复需另行验收。

## 4. 数据模型（最低实现要求）
- `instrument(id, code CHAR(2) UNIQUE, name, active)`
- `category(id, code CHAR(2) UNIQUE, name, active)`
- `settings(key,value)`：含输出路径、首次初始化状态等；编号规则固定为全局流水，无作用域切换设置。
- `song(id, category_id, seq CHAR(3), base_title, normalized_title, display_title, version_no INT, status, created_at)`；正式编号必须**跨全部分类全局唯一**（数据库 `UNIQUE(seq)` 或等价保留编号表）；未编号草稿 `seq` 可为 NULL；同基础标题不同版本有独立 song_id。
- `song.minimum_waived`：默认0，仅用户明确强制收录不足分类最少数量的普通声部时置1；后续补谱不重新要求凑齐，重开、改名和备份恢复保留。旧库/旧清空备份缺少字段时按0兼容，不自动改变既有曲目规则。`force_archive`审计记录所选分谱、真实数量、最少数量与实际豁免。
- `score(id, song_id, instrument_id, source_name, source_path, source_sha256, output_name, created_at)`；同曲目版本同乐器重复提交时必须检查冲突。
- `title_alias(id, category_id, alias_title, song_id, confirmed_at)`；用户确认后记录。
- `import_batch(id, state, created_at)`、`import_item(id, batch_id, source_path, status, parsed_fields, decision)`。
- `warning(id, batch_id, song_id, code, severity, state, details, resolution, updated_at)`。
- `operation_log(id, batch_id, song_id, action, old_path, new_path, state, timestamp)`；用于恢复和审计。
- SQLite 必须开外键约束、建立有效唯一约束、事务，避免重复编号。可以按实际实现合理拆表，但上述数据不得丢失。

## 6. 阶段划分与硬性验收门

### M0 · 工程初始化与安全基线
**实现**：目录结构、可启动 GUI 壳、数据库初始化、配置持久化、7种乐器与可编辑自定义分类；固定全局三位序号分配基础；基础测试框架。
**通过**：程序可启动、重开分类配置不丢失、数据库拒绝跨分类重复曲目序号、单元测试通过。

### M1 · 批量导入与编号解析
**实现**：批量/文件夹导入、严格解析旧4位与新7位规则、未知编号待补录、多选人工修改、草稿持久化。
**通过**：无/错编号不会被虚构分类；已知规则正确；重启后草稿能继续；源文件校验哈希不变。

### M2 · 曲目归组与预警（先不写入正式目录）
**实现**：曲名相似候选、分组、别名确认、版本确认、重复文件及乐器冲突、固定预警栏、逐曲报告。
**通过**：相似曲名不被自动合并；不同版本有独立身份；两份同乐器不算两种；用户能在预警栏定位修改并重新校验。

### M3 · 编号与双目录归档
**实现**：按全库统一流水分配三位编号，预览输出方案，按两套目录写入，失败回滚/恢复，补谱 `（06）→（07）`，完成整批汇总。
**通过**：二套PDF内容哈希一致；原件未变；二次执行不重复；冲突不覆盖；失败不产生“成功”记录；补谱不改变原编号。

### M4 · 日志、备份、易用性与 Windows 成品
**实现**：整理历史、数据库/索引备份恢复、中文路径/长文件名验证、可理解的错误提示、Windows打包与使用说明。
**通过**：实际 Windows 电脑上可双击运行（无需Python命令行）；使用至少一批用户真实PDF全流程测试；备份可恢复已有曲目编号、版本和输出关系；关键测试全部通过。

**开发流程**：一个里程碑内按最小模块推进，每模块都要“实现 → 测试 → 缺陷修复 → 复测 → 更新 `PROGRESS.md`”，**不得为赶进度跳过**。
