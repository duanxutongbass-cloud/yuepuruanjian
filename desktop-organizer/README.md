## 基本使用

### 独立迁移候选的只读检查（开发验证入口）

已准备独立候选时，可在 `desktop-organizer` 目录使用源码环境执行：

```powershell
.\.venv\Scripts\python.exe -m score_organizer.services.runtime_candidate "D:\候选目录\prepared.json"
```

参数必须是 `prepare_relocated_library` 返回的实际完成清单路径；示例路径不能直接照抄。成功时退出码为 0，标准输出为 JSON，包含 `verified: true` 和 `activationAllowed: false`；这只是本次文件、数据库和独立副本核验结果，不是启用许可。候选损坏或缺失时退出码为 3，原因写入错误输出；参数错误为 2。不会启动界面、创建缺失数据库、读取默认旧库或修复候选，也不写检查报告文件。需要留存结果时请自行重定向到候选目录之外的新文件。

正式整理入口仍使用现有库和 999 上限；本检查不开放 1000 号，不提供可写连接或旧 EXE 隔离证明。后续启用前仍须重新核验并完成隔离与三端兼容。

### 总谱与编号归档规则

07仍是打击乐，08是总谱，09是总谱+分谱。08/09默认一份即可正式入库，只保存到输出位置的`按乐器分类/08总谱`或`按乐器分类/09总谱+分谱`，不在按曲目分类再复制一份。仍显示在已入库目录、参与重复检查，使用相同的全库三位曲目流水。

顶部“设置 → 编号归档规则”可分别设置每个乐器编号的存档方式（双目录或单份、仅按乐器分类），以及每个分类的普通分谱最少不同乐器数（默认3）。保存前确认并备份；旧库文件、编号和已保存的副本数不会因规则修改而改变。仅支持这些明确设置，不支持任意脚本规则或取消重复/覆盖检查。

### 菜单与右键

主界面保留“导入乐谱”下拉按钮、打开选中PDF、校对选中分谱、确认入库、查看曲谱库。草稿多选后右键可打开PDF、校对、归入指定曲目、对比重复、暂存无用谱、转入待审查或移除；右击已选行保留多选，右击未选行只选择该行，不会处理上次选中的其他文件。所有表格仍可右键查看完整信息。预警右键可处理、打开关联PDF、查看重复或仅确认提示；后者不会修改或入库。

顶部“文件”管理导入与输出位置；“分谱处理”提供选中分谱及预警操作；“乐谱库”查看正式库、待审查、暂存及重复目录；“设置”管理分类、乐器和归档规则；“数据管理”提供清空与恢复，不再把危险清空操作放在底部常用按钮旁。

“设置 → 乐器管理”可以新增两位编号（00～99）及名称，选择双目录或单份入库规则；保存前确认并备份，新编号立即用于后续导入、校对与规则管理，重启保留。已有编号通过选择表格记录编辑，不能用“新增”覆盖旧编号，也不允许直接改编号；已经有入库分谱的乐器不能直接改名，避免存档路径失效。未入库的名称可修改，草稿仍引用该乐器时不能停用；停用不删除历史记录。分类管理同样移到“设置 → 分类管理”。

已确认相似分谱属于库内同一首时，多选后右键“强制归入指定曲目并入库…”：选择并对照库内标准曲目，确认所选分谱曲名/分类/编号修改预览，再勾选强制正式入库并确认。只校对和入库选中草稿，沿用正式曲目编号，源PDF和未选中草稿不改。即使只有一个普通声部，也可正式收录；仅豁免这首曲目的最少声部数，重复、同乐器冲突和文件变化仍检查。已有同乐器分谱会列出对比供确认取舍。取消归属或校对预览不改草稿；校对确认后取消入库则保留已保存草稿，不冒称入库。

要独立新建一首，不必先选库内曲目：在草稿中选中该曲目的分谱，右键或顶部“分谱处理 → 强制新建独立曲目入库…”，填写统一曲名和分类、核对乐器，再点击“强制入库”。先确认校对清单，再核对新编号和全部原名→新名入库表，勾选“确认强制正式入库（允许仅一个声部）”并确认。一个普通声部也能进入正式双目录；旧草稿归属及流水会解除，原编号保存在记录中，正式库旧曲目和原PDF不动。普通校对窗口的“归入曲目”也可选择“新建独立曲目（分配新编号）”，只保存草稿后重开仍保留这个选择。

普通新建仍按配置检查最少乐器数，08/09仍可单份。强制收录普通声部不足的曲目后，目录注明“强制入库，声部待补齐”，数量按实际显示，不伪装成完整重奏；后续正常补谱沿用原号，不必再凑3份，其他曲目的默认规则不变。两种新建都检查重复；库内已有同分类同名（含仅空格不同）时不能误拆，需选择已有曲目或为确实不同的作品填写可区分的名称。选中多首时先分别处理。取消校对不改数据；确认校对后取消正式预览保留草稿、不占正式号。普通新建总谱先入库、普通分谱后来补齐时沿用这次新号；确认后库中出现同名曲目会提示重新选择，不静默改成补入。

新建时如果草稿还有同分类同名或仅空格不同的分谱，软件会自动把它们带到当前校对窗口，一起选中并列入修改预览，不再要求退回草稿箱自行寻找。原先填写的内容保留，新增分谱可直接打开PDF核对；确认清单后才保存。仅名称相似、分类不同、版本名称不同的文件不会自动带入；发现不是同曲可取消预览，改选并填写可区分名称。重复/同乐器冲突和缺失PDF不会因带入而跳过；预览后又新增同名文件时，会带入并要求重新确认。

总谱不算一种普通演奏乐器。混合导入总谱与尚未补齐的普通分谱时，可先入库总谱，普通分谱继续留在草稿；后续补齐沿用同曲编号。已入库改名、重复对比、合并及备份恢复都按实际存档副本处理，单份类型不要求第二份PDF。以下常规“三种乐器/双目录”说明对单份类型不适用。

### 常规整理

1. 启动软件。
2. 从“文件 → 选择输出文件夹”或右侧文件夹按钮选择输出位置，选择后自动保存。
3. 从“导入乐谱”下拉选择“导入乐谱文件”或“导入整个文件夹”。
4. 查看中间草稿表和右侧预警表。
5. 选中有问题的预警，点击“处理选中预警”；也可选中草稿分谱，点击“校对选中分谱”。
6. 校对窗口默认只选第一份分谱，选中哪份就单独修改哪份的曲名、分类及乐器，不强制把相似曲名统一。需要批量统一时先多选或点击“选择全部分谱”；要补入已有曲目，在“归入曲目”下拉列表选定对应编号及曲名。
7. 点击“校对并入库”，先确认校对修改，再确认原名→新名及两套目录的入库预览。按钮右侧箭头可直接选择“强制新建独立曲目入库”或“强制归入已有曲目并入库”，不用退出窗口；当前名称、分类、乐器和选中分谱直接参与校对。仅保存时选择“保存校对到草稿”。

普通入库提示声部不足后，可在同一窗口点击入库按钮旁箭头选择强制新建；已有曲目则选强制归入，未选库内目标时会打开候选选择，已选有效目标直接复用。归入已有曲目采用库内标准名称及原编号，当前乐器修改保留；强制新建采用当前独立曲目的名称和分类。在同一个最终预览中核对校对清单、最终文件名和目标目录，强制入库在这里勾选，不再另弹一次校对确认。取消候选或最终预览不保存本次修改，留在当前窗口保留输入。下拉“普通校对并入库”仍遵守最少声部规则。

“保存校对到草稿”只保存窗口内当前选中的分谱，窗口不关闭，能继续点另一份分别修改。下方显示本次选中份数，预览只列出这些文件；未选中的名称、分类和乐器不改。切换选择会保留该窗口内尚未保存的字段，返回原选择可继续编辑；未确认保存的编辑不会写入数据库，关闭后放弃。真正不同的曲目可保持各自名字，例如“千与千寻《再度》”与“千与千寻《与你+再度》”。

与库内名称相似、确认属于同一首时，选中需要统一的分谱，点击“统一为库内名称”，选定正式曲目并“采用库内名称”，再确认校对预览并保存或入库。曲名、分类和编号直接采用库内值，不需要手打空格或括号；只修改实际选择，不改原始PDF和正式曲目记录。选择列表只包含正式曲目，可打开库内PDF对比；再次打开校对时保留已经明确的库内归属。没有确认前，库内相似曲名仅作为候选提示，不自动合并。

确认库内归属后，只要标准名称、分类、编号与唯一的正式目标仍一致，不再重复要求删除库内名称的乐器后缀、确认已有版本标记或重新判断该份的名字相似；目标变更、失效或歧义时重新校验。重复内容、同乐器多份、缺少乐器、编号或写入冲突仍正常检查。校对后入库失败在当前窗口保留具体原因，不反复弹出笼统的命名警告；“查看未入库原因”可读完整文件名和全部问题。信息性相似提示不会被当作阻断原因：缺谱显示实际乐器数，重复明确说明改名不会消除内容重复，写入失败显示真实错误。新曲目若有库内相似名称，同时列出候选标准名称供确认。

点击“查找疑似对应曲目”会按文件名曲名对照当前草稿和已入库目录，显示完整曲名、分类、已有编号及名称相似度。可搜索其他名称/编号，或取消“仅显示疑似对应”查看全部；相似度不是PDF内容判断，不自动确认同曲。选中候选可打开分谱对照（已入库使用库内副本），点击“归入选中曲目”只填写当前选中分谱的归属，仍需确认原值→新值才保存。候选草稿本身及未选中分谱不修改；候选被删、字段或PDF在预览后改变会阻止提交，取消查找不改变已有校对。

普通校对并入库只整理本次校对涉及的曲目；同曲目其他草稿分谱一起纳入预览，无关曲目不入库。强制入库只提交明确选中的分谱，并允许豁免声部数量。成功的分谱移出草稿；仍有重复、同乐器冲突或普通新建数量不足的分谱保留草稿并列出原因，可继续处理或保存到待审查。完整或已强制收录的曲目允许补入一份新乐器分谱，不必重新凑3份。指定已有曲目时校对的是草稿归属，原始PDF和库内已有编号不变；目标存在完全同名误拆记录时先合并或区分名称，不猜测取舍。

正常“校对并入库”只需一次最终确认：同一窗口显示校对字段变化和正式输出方案，确认后保存并入库，完成结果显示主界面及状态栏，不再弹成功框。取消最终预览不保存这次修改；之前已经保存的草稿保留。尚有重复或声部不足等阻断时，可先确认校对保存到草稿，再解决问题；重复取舍及替换旧谱仍需明确选择。最终确认后若文件或入库方案变化，会停止写入并要求重新核对。

校对窗口提供“对比并处理重复”，带入当前选中的草稿及已知对比文件；即使名字不同、没有编号或程序没有识别为重复，也可以勾选后人工确认转存，不必先改名。尚未保存的校对字段不会应用。“仅确认提示无须修改”只记录提示结论，不代替实际转存或入库。

导入文件或文件夹后，如这次新增分谱已有库内对应文件，会立即弹出“已有入库乐谱：确认是否转入重复库”，列出草稿与库内分谱的编号、曲名、乐器、文件名和可打开的PDF路径。即使文件被改名或没有编号，内容完全相同也能识别；点击“确认完全相同文件转入重复库”可一次确认这些副本，不必先补录曲名。仅同曲同乐器但内容不同的文件不自动判重复，需打开对比、勾选确认后转存。

点击入库（含校对后入库）会再次检查；例如第一小提琴《天空之城》已有库内分谱，会先询问是否转入重复库，不覆盖库内文件。取消则保留草稿、不再次入库；也可选择“暂不转存，继续入库无冲突分谱”，问题文件保留草稿，正常曲目继续预览入库。确认转存复用“已确认重复”目录及说明清单，核对选中记录及复制完整后才移出草稿；完全相同快捷处理另核对库内保留件，人工确认不受名称是否相同限制。失败保留草稿。导入提示只处理本次新增文件，不混入以前尚未确认的草稿。

如果新谱更好，在这个对比窗口选中新草稿行，点击“保留选中新谱入库，旧谱转入重复库”。也可勾选多份新谱批量处理；若对应多个库内目标，须同时选中明确要替换的库内行。替换预览可打开新旧PDF，展示保留的新谱、原库文件和旧谱转存位置；勾选确认属于同一版本，再“备份并确认替换”。尚未识别的文件先校对乐器；不同版本不要使用替换，仍应按新增版本处理。

替换沿用原曲目编号、标准名称、分类和存档方式，不增加曲目或乐器数量；普通分谱同步替换两套正式副本，总谱等原单份谱仍只替换一份。旧谱保存到 `已确认重复/原曲名` 下并标注重复序号，每份旧分谱只转存一个PDF，附原路径与替换记录；新谱成功后移出草稿。执行前备份数据库、新谱及全部旧副本到 `修改备份/替换分谱_批次`，原始新旧PDF不动。取消不写入，文件或记录变化阻止提交；可捕获失败回退，恢复受阻或提交后的清理失败明确提示“停止整理”并保留备份。不要把异常后可能已提交的操作当作未入库再次执行。

文件名包含 `HANDCLAP-小提琴_1`、`HANDCLAP-中提琴`、`HANDCLAP-钢琴` 等乐器后缀时，预警中心会把同分类、同建议曲名的相关分谱列为一条“乐器后缀需统一曲名”。选中后点击“处理选中预警”，窗口建议填入 `HANDCLAP` 并列出所有相关分谱；确认原曲名→统一曲名后可一次入库为一首曲目。也可以多选草稿，直接“校对选中分谱并入库”，匹配明确时同样提供建议。确认前仍保留原解析曲名，不自动合并；取消不修改。只识别与编号所对应乐器名称匹配的末尾标注，不删除曲名中间的乐器文字，不跨分类合并，不移除“第二版”等版本文字。原始PDF不改名，校对后仍须检查重复、同乐器多份和编号冲突。

## 查看完整名称与问题

表格中长名称的省略号只表示列宽不足，不是把名称改短了。主表默认按窗口分配名称列宽，让乐器、编号及状态保持可见；手动拉宽后保留你的列宽，必要时通过横向滚动查看，不自动缩回。鼠标停在文字上可显示完整值。草稿上方“查看完整信息”会列出所选分谱的完整原名、曲名、新文件名、编号、状态和源路径，支持多选；预警右键“查看完整信息”或“分谱处理 → 预警操作 → 查看预警完整详情”显示完整问题文字及关联PDF路径。

曲目报告、已入库目录、校对预览、重复对比和待审查等表格也可在记录上右键选择“查看完整信息”。窗口只读、长文字自动换行，可选中复制，不会修改曲名、编号或PDF；双击打开PDF的原有操作保持不变。

程序不会修改或删除原始 PDF。正式归档会复制到：

- `按乐器分类`
- `按曲目分类`

不足3种乐器、重复或命名不明确时，先在草稿中选中文件，通过右键或顶部“分谱处理 → 选中分谱转入待审查”，核对文件和原因后保存。选一份只转一份，多选只转选中的文件，不会自动带走同曲其他声部或整个草稿箱；没有选中时不会转存。无预警但主动选择审查的文件标记“人工指定待审查”。文件位于输出文件夹的 `待审查` 下，按批次和原因分目录，每份附有 `审查说明.txt`，批次附有 `审查清单.txt`。原文件保留，转存成功的记录移出草稿，其余草稿不动。

点击“查看待审查文件”可搜索原因、打开PDF，并把选中文件“放回草稿继续整理”。已补录的分类、乐器和曲名会保留；补齐并解决问题后再正式归档。待审查清单JSON用于恢复校对信息，请与对应PDF一起保留。

暂时不需要整理的分谱，可在上方草稿表多选后点击“暂时无用：转存选中分谱”，核对原名→暂存名并确认。选中的PDF全部直接放在输出位置的 `暂时无用乐谱` 文件夹，不按曲目、批次或分谱建立子文件夹；原文件名尽量保留，同名副本加 `（同名2）`、`（同名3）`，不覆盖。复制核对成功后才移出草稿，原始PDF及正式库不变，不占流水、不要求3种乐器，也不自动判重复。附统一文本/JSON暂存清单，保留源路径、指纹和校对字段；取消不写入，保存失败保留草稿并回退新增副本，回退失败明确提示。

点击“查看暂时无用乐谱”可搜索文件、打开PDF、打开统一文件夹，或多选后“放回草稿继续整理”。放回时保留校对信息并核对副本，文件夹内的保存副本保留，已放回的记录不再显示为待整理；重新放回同一记录不会重复导入。清单请与PDF一起保留。

归档被重复或同乐器冲突阻断时，会自动打开“重复文件对比与处理”。也可点击右侧“查看重复文件并处理”，核对草稿与库内文件的名字、完整路径和PDF。左侧勾选框支持跨组批量选择；“勾选完全相同的多余副本”只勾选指纹完全相同的多余份数，无库内副本时每组保留最早导入的一份，不选择指纹不同的版本。点击“确认选中重复并转存”，一批只需一次确认；也可“勾选可见草稿”后取消勾选要保留的分谱，或使用“保留选中，其他分谱转存已确认重复”。搜索后这些操作只处理可见范围；“取消全部勾选”清除选择。原有Ctrl/Shift多选仍可使用。库内行不能勾选转存；“确认并转存全批已入库相同副本”明确针对全批，不受搜索限制。

确认窗口显示涉及组数和PDF份数，核对后保存到输出根目录的 `已确认重复/曲名/乐器标注-曲名（重复1）.pdf`。例如 `已确认重复/天空之城/01第一小提琴-天空之城（重复1）.pdf`，第二份为“重复2”，后续导入继续递增，不覆盖已有文件。一首曲目一个文件夹，PDF直接放在里面，不再按日期批次或每份分谱套文件夹；完全相同且已入库的文件优先使用明确的库内曲名，无法明确时保留校对曲名或原文件名作为命名依据。非法/超长目录字符会作安全处理，完整曲名和原名保存在清单中。

你明确确认的草稿就按重复转存，不再要求曲名、分类、乐器或内容指纹相同，也不要求程序先识别为重复；全部明确选中的草稿均可转存。自动选择完全相同副本仍保留最早导入的一份或已核验的库内分谱，不自动替你判断不同版本。曲目文件夹统一附 `重复确认说明.txt` 和文本/JSON清单，重复目录根部有总清单，记录原始路径、分类、乐器、校对字段、已知对比件及人工确认结论；复制件校验成功后才移出所选草稿，记录或源文件变化时停止，失败整批回退。原始PDF和库内文件保留，可点击“打开已确认重复文件夹”查看副本。处理完返回继续正式归档。

已有日期批次目录可选择“乐谱库 → 整理旧重复目录”：先预览曲名文件夹与旧名→新名，再“备份并确认整理”。会核对所有已登记PDF，保存数据库快照，并将旧目录及说明完整转入 `修改备份/重复目录整理` 下；新PDF按曲名直接存放。取消不改变目录；文件缺失、变化、未登记PDF或旧目录中有正在作为源PDF引用的文件时会阻止整理，可捕获失败回退。已有旧合并重复目录也支持转换，原有两套保存副本都保留；新合并的重复副本直接按曲名存放，逐次对比记录单独保留，不覆盖其他确认说明。

“查看已入库目录”每次打开时读取最新入库记录，以每首曲目一行显示乐器数和分谱数，点开查看各分谱。不同正式编号的版本分开显示，真正的同乐器多份会提示核对。选中一首曲目，点击“修改选中曲目的曲名和分类”，填写后点击“预览修改”，核对两套目录的原名→新名清单，再“确认修改两套目录”。曲目序号及版本身份保持不变，成功后目录立即更新，后续补谱沿用原序号。

目录顶部“曲目分类”可直接选择“01 久石让”“02 电影音乐”等自定义分类，也可切回“全部分类”；按分类编码精确筛选，不会把曲目编号里的数字误当成分类。搜索框可在所选分类内继续查曲名或编号，右侧显示当前/全库曲目数。切换后被隐藏的曲目会取消选中，避免误编辑；修改分类后自动显示新分类及刚修改的曲目。筛选只改变显示，不移动PDF或更改编号。

修改前数据库、PDF及操作清单保存在输出根目录的 `修改备份/批次` 下。目标重名、文件缺失或哈希变化会阻止修改；执行中遇到可捕获失败会恢复原记录和文件。原始PDF不修改，库内文件被用作源PDF时会阻止改动。曲名和分类编辑不直接修改正式流水编号。

## 误拆曲目合并

如果同一首因空格差异变成两条记录，在“查看已入库目录”选中要保留编号的一条，再点击“合并误拆曲目”，选择另一条并填写统一曲名。同乐器多份可选中后“打开选中PDF”对比，必须逐份选择“保留”或“确认重复并转存”；每种乐器只能保留一份。如果是不同编配版本，请取消合并，不要确认重复。

勾选确认后点击“预览合并”，核对旧名→新名及两套输出目标，再“备份并确认合并”。软件保留选定编号，另一编号不再作为独立正式曲目显示，但继续保留占号记录，不分配给新曲目。未保留的库内分谱副本转存至“已确认重复”，包含人工确认和对比记录；原始PDF不变。数据库和全部旧副本保存到“修改备份”。可捕获失败会回退；当前仅支持同分类、同版本、同名或仅空格不同的误拆，不是任意重新编号。

## 全部清空与恢复

顶部“数据管理 → 清空全部整理数据”会先列出范围，勾选确认后备份并清空：草稿、已入库记录、预警、导入历史，以及当前输出位置下的按乐器分类、按曲目分类、待审查、已确认重复、修改备份和暂时无用乐谱目录。旧数据库和整理结果保存在 `清空备份/批次` 中，原始PDF及分类/乐器配置保留，新的空库从001开始。输出位置下其他用户文件和已有清空备份不动；整理目录中存在正在作为源PDF使用的文件时会阻止清空，避免改变原件。

“数据管理”菜单可打开最近清空备份，或“恢复上次清空”。恢复前也保存数据库快照；恢复不能覆盖新导入记录或新整理目录。已有新数据时会阻止恢复，未成功清空/已恢复/损坏的备份也不会直接覆盖当前库。清空或恢复遇到可捕获失败会回退，部分回退未完成时明确给出备份位置并要求停止整理。

## 保存性能验证

批量导入先逐份校验原件，再一次提交整批草稿；保存和入库后只做一次预警扫描及表格刷新。单次操作复用数据库连接，不缓存跨操作的库状态，也不省略重复检测、正式预览及文件哈希核对。

在本机隔离的450份约64KiB测试文件上，三轮优化后测量：保存后刷新从21.21秒降到0.12～0.44秒，单曲3份分谱入库提交从7.33秒降到0.38～0.83秒，批量导入从13.52秒降到8.17～9.09秒。测试文件不代表用户真实PDF，实际耗时受文件大小、磁盘和文件打开速度影响。

复测命令：`.\.venv\Scripts\python.exe scripts/benchmark_save.py --label local`。只在项目 `work/save-benchmark` 新建隔离测试库及输出，记录耗时、连接次数和分析结果，检查归档双副本及原件哈希，不操作现有曲谱库。

## 节目单打包

顶部“节目单打包 → 新建或载入节目单”：输入一两个字搜索曲名，也可输入分类名称/编号或选择分类。多选后“添加到节目单”，或双击添加。右侧填写节目序号，也可用上下箭头调整；序号不能重复，正式库原编号不变。

选择乐谱库之外的打包位置，点击“预览并打包”，核对节目顺序、原文件和缺谱清单后确认。例如第一小提琴会得到 `01 第一小提琴/001 天空之城.pdf`、`01 第一小提琴/002 哈利波特.pdf`，其他专业保持相同节目序号；某专业缺谱时保留序号空缺并列出原因，不补造PDF。

结果包含各专业独立PDF、节目单文本和JSON，可勾选同时生成“节目乐谱.zip”。“打开打包文件夹”直接查看；“保存节目单/载入节目单”可重复使用，打包结果内的“节目单.json”也可载入。同名结果不会覆盖，请改节目单名称或换位置。只复制已入库谱，原件、正式库和流水不动；库内PDF损坏/缺失或同乐器多份时先修复，不自动取舍。后台核对与复制期间请等待完成再关闭窗口。

## 打包方法

安装 PyInstaller 后运行：

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
.\.venv\Scripts\pyinstaller.exe packaging\score_organizer.spec
```

2026-10-14已在本机Windows 11完成PyInstaller 6.22.3构建、隔离用户目录启动、主界面及节目单窗口检查和正常退出；完整回归510项通过。尚未在另一台Windows 10/11或用户真实PDF整库上完成成品验收。程序未经数字签名。

必须保留EXE旁的完整`_internal`目录。打包配置已避免构建机PATH中的Poppler ICU DLL覆盖Windows系统ICU，并统一界面所需VC运行时；不要手动删DLL。源码要求Python 3.12或以上。

生成干净交付目录：运行`scripts/create_delivery.py 目标目录 --build PyInstaller生成的程序目录`，再运行`scripts/create_delivery.py 目标目录 --finalize`创建ZIP并核对CRC和每个文件SHA-256。目录已存在不覆盖，源码只按白名单复制，排除数据库、PDF、work、虚拟环境及缓存；依赖版本及许可随包保存。运行`scripts/package_smoke.py EXE路径 隔离用户目录`可复测启动，关闭测试窗口后脚本应输出`PACKAGED_EXE_CLOSED_OK`。
