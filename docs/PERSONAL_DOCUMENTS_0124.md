# 0.10.24 个人文件（仅本机）

普通登录账号在“我的 → 个人文件（仅本机）”通过系统选择器导入 PDF 的独立副本，可以打开、逐页阅读、搜索、移入个人回收站及恢复。回收站内的“彻底删除”先显示本账号文件及大小，必须勾选不可恢复确认，才会清理登记的本机副本。外部原件保留。

这是独立的本机文件区，不是 NAS 个人云盘，不随团队同步。现有曲库备份和个人批注备份暂不包含这个文件区；卸载、清除应用数据或设备损坏会丢失本机副本，需保留外部原件。个人 PDF 当前只提供基本逐页阅读，未接入团队排练、节目单或批注流程。

以规范化服务器地址和登录账号 UUID 绑定所有权，不按管理员角色、乐团成员 ID 或下载授权推断源文件所有权。普通账号不会获得团队源谱管理权限；既有团队下载、旧本地库及未登记文件不会被自动接管或清除。登出和换账号关闭旧预览与确认框，异步选择器结果和旧操作须再次核对当前所有者。

文件存放在 Context 可信 noBackupFilesDir 父目录规范化后的 personal-documents-v1/账号摘要/scores/UUID.pdf。AES-GCM 原子保存的 index.enc 同时绑定服务器和账号；目录、文件身份、大小、哈希、状态和修订号全部核对。只规范化 Context 父目录，子目录/文件别名仍拒绝，不能借路径变更读取或删除其他文件。Room 仍为 6，服务仍为 0.10.22／库 4／命名 2。

彻底删除先持久保存退休身份和清理意图，再删除已核对副本，完成后才移除目录记录。中断/磁盘失败保留不可打开、不可恢复的清理中状态；刷新可继续此前明确授权的清理。其他个人文件仍可使用。未知、错身份或损坏记录不会当作空库，也不会触发猜测清理。

本机自动化、Compose 确认界面绘制及构建结果另见交付校验清单。真实 Android PDF 导入／渲染／翻页验收用例在 src/androidTest/.../personal/PersonalPdfNativeTest.kt，尚未运行，不能称原生 PDF 已通过。Robolectric 4.16 没有 PdfRenderer shadow；先前 API35 方法缺失、API34 页数为零的两轮主机失败证据均保留，未改 PDF 页数或完整性断言。该测试应在 Android 环境执行，纳入 AndroidTest 包；Codex 未操作用户平板。

真实平板验收由用户本人进行，自动化通过不代表真机通过。复测建议：普通成员导入一个自有 PDF，阅读与翻页，删除后恢复；再删除并核对勾选确认范围；换账号检查文件列表隔离，重新登录原账号检查仍可使用。不要重复删除 NAS 真实源谱来验证本机根目录修复。
