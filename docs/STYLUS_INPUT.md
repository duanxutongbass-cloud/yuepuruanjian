## 操作与范围

- 工具栏提供“手指书写／手写笔优先”，当前模式始终可见。这是本设备的输入偏好，不含账号或乐谱内容；原用户默认保留手指书写，选定模式在应用重开后沿用，不按探测到的笔静默切换。模式写入使用 Android 私有偏好异步持久化。
- 手写笔优先时，谱面上的手指、手掌和鼠标不生成批注，也不触发翻页。手指翻页与缩放先选择已有“阅读”工具；工具栏按钮仍可正常用手指操作。设备将笔上报为普通触摸（例如部分电容笔）时，需主动选择“手指书写”。
- 每笔只跟踪一个稳定 pointer ID，指针数组顺序变化不串点。笔先落下再放手掌、手掌先落下再连续写笔，均独立处理；手掌抬起被系统标记取消时不丢弃有效笔迹。手指书写中笔落下会取消尚未完成的手指笔画，再接收该支笔。第二根手指取消未完成手指笔画，两个笔触点同时接触也取消，不自动续接剩余触点。
- 系统 ACTION_CANCEL、笔的 FLAG_CANCELED、源页/变换/工具/模式或可编辑状态变化、丢失所属指针、越出谱面、超过 4096 点上限时，取消当前未完成笔画，已完成笔迹保留。忽略的手掌不另造笔画，也不进入恢复副本。历史采样按实际顺序接入，溢出不保存截断笔画。
- 设备如上报 TOOL_TYPE_ERASER，笔尾暂时调用原有整笔擦除，可撤销；不改当前选择的工具，也不能绕过只读、锁定、逐谱授权或图层权限。笔迹完成后仍经过原有页容量、保存与加密恢复链路，共享草稿仍需显式发布。

## 明确未验收

本批不启用压感变宽、倾斜、侧键或低延迟前缓冲，也不宣称已解决所有设备的手掌识别或物理屏闪。没有真实手写笔和普通/大平板的硬件输入、帧时延、刷新率或真实排练验证；M-Pencil 等设备的工具类型、笔尾上报能力需用户实测。真实设备若只上报普通手指，应用无法自行辨别其物理来源。

输入 API 与取消行为按 [Android 官方 Compose 手写笔指南](https://developer.android.com/develop/ui/compose/touch-input/stylus-input/advanced-stylus-features) 核对；系统对某指针的取消不得误删另一支有效笔。没有改原 PDF、编号、数据库 schema、NAS API 或诊断事件白名单。
