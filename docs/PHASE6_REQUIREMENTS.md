# Phase 6：蓝牙脚踏与连续演出流

状态：2026-10-09 软件范围完成并通过，结果见 PHASE6_REVIEW；物理蓝牙脚踏验收待真机。依据主项目最新阶段确认；继承 DEVELOPMENT_RULES 和 PRODUCT_DESIGN。

## 范围

- 使用 Android KeyEvent / HID 输入，近期以 Android 系统已配对的蓝牙 HID 脚踏为主，也兼容相同协议的外接键盘/USB HID。
- 脚踏按键学习、测试、持久化自定义映射和显式开关；防重复触发、长按和抖动。
- 上一页/下一页统一使用 PedalAction，触屏入口与脚踏共用连续流控制逻辑。
- 当前曲第一页向前进入上一曲最后一页；最后一页向后进入下一曲第一页。始终消费 Domain 的 ResolvedConcert 顺序和个人分配声部，不自行猜声部。
- 曲目切换无确认弹窗；第一曲/最后一曲的全局边界只给弱提示，不循环、不越界。
- 脚踏断开不阻塞阅读，普通页面/文本输入不被翻页拦截；配置变化后正确恢复位置与映射。
- 保护批注手势与保存，不让脚踏中途切页；演出流使用已发布/锁定共享层，不展示管理员草稿。
- 缺谱、损坏、授权/节目单变化必须明确失败，不跳过曲目或错误回退到其他声部。

## 核心验收

五首曲目 → 从第一首进入 → 只用 HID 按键逐页推进 → 正确跨曲和声部 → 第五首结束弱提示。覆盖反向跨曲、重复/抖动、加载时输入、断开、退出、配置恢复与权限更新。

实际运行 Gradle 构建、JVM/Room/Android 测试、Lint 和普通/大 Pad 可视检查。KeyEvent 模拟不冒充真实蓝牙无线、配对、断连重连和厂商固件验收；非 HID 的专用 BLE/GATT 协议未冻结，不引入未确认的协议库。

完整演出模式和离线可靠性仍是 Phase 7，完整管理 Phase 8，物理设备性能/硬件验收 Phase 9，NAS 与商业版按后续规划。
