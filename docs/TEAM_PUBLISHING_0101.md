本批继续编号 3、4。Android 保持 0.10.0；服务与电脑端发布包为新一批交付。尚未实现编号 5 的平板自动同步，因此服务器发布成功不代表旧版 App 曲库已自动出现乐谱。

## 电脑端使用

完整解压 `ScoreOrganizer-publishing.zip`，双击 `Start.cmd`。本机新版与此前 `ScoreOrganizer` 同级时沿用 `ScoreOrganizer/data`；原可执行程序保留。迁移库时仍须备份并迁移数据库和实际 PDF 目录，不只复制程序。

打开“团队发布 → 选择分谱并发布给成员”，输入已配置证书的独立 HTTPS 服务地址，以管理员身份登录。选择分谱、勾选成员，点击“分配接收成员”；不同分谱可指定不同成员。搜索只清除当前行选择，已分配的完整清单仍在发布预览中。生成预览后逐份核对，勾选独立分谱确认，再确认上传发布。总谱+分谱（09）组合文件禁止当独立分谱发布；PDF 内容属于哪些声部仍由管理员核实，不做内容识别。

每份谱保留乐器+分类+三位流水编号、分类名、乐器名、标题。发布前及提交前复核数据库记录、所有按归档规则保存的副本哈希。原始 PDF、正式编号、双目录和本地归档记录不被发布操作修改。

连接只接受干净 HTTPS 源地址，验证系统证书，不跟随跳转；密码与会话只存在内存。仅保存服务地址和非秘密设备 UUID。关闭窗口尝试退出登录；断网退出时服务端会话按原 12 小时期限失效。成员列表由服务端返回，默认不勾选任何接收者。

## 发布协议

- `POST /v1/admin/uploads`：管理员创建上传计划，包含请求 UUID、编号、分类、标题、乐器、SHA-256、长度及独立谱确认；返回上传 UUID。相同请求参数幂等，冲突拒绝。
- `POST /v1/admin/uploads/{UUID}/content`：有界流式 PDF 上传，每份最大 100 MiB；读取前鉴权，完成后再次核对会话；校验长度、哈希、PDF 格式及页数后提交不可变暂存文件。
- `POST /v1/admin/publications`：最多 50 份谱，逐份明确成员 ID；全清单验证通过后在一个事务内发布、授权并保存回执。JSON 最大 16 KiB，客户端预览时也校验。无效成员、缺文件或变更均回滚。

同一电脑、同一账号、同一文件元数据及接收清单重试会返回同一回执；不会重复生成谱，也不会重新恢复随后撤销的权限。调整接收清单会形成新的发布副本；当前不自动替换旧发布，旧授权仍可经管理员 API 撤销。未完成的上传不会进入成员目录，失效未完成请求可重建；已有完整暂存文件不自动删除。需管理员后续制定保留/清理策略，不能把重复请求当清理命令。

## 完整备份恢复

在容器内使用现有入口（省略 `python server.py --data /data` 前缀时是 Docker ENTRYPOINT 的子命令）：

```text
python /app/server.py --data /data backup-full --output /data/backups/team-20261015.zip
python /app/server.py --data /data verify-backup --archive /data/backups/team-20261015.zip
python /app/server.py --data /data-restored restore-full --archive /data/backups/team-20261015.zip
```

输出父目录须预先创建且由容器 UID 10001 可写。恢复目标必须不存在，父目录已存在且可写；不能覆盖正在运行的数据目录。恢复后先验证新目录，再停服务并由管理员将数据卷切换到恢复目录。不要将完整备份放在公开下载路径，备份包含账号密码哈希和受限 PDF。

备份持有数据库写锁捕获一致快照，打包数据库及全部已提交 PDF，附 SHA-256 清单，校验后才发布最终 ZIP 名称；并发上传临时文件排除。恢复检查路径、重复/额外条目、哈希、SQLite 完整性及外键、数据库与 PDF 一致性，重新登录和重新签发邀请；不恢复旧会话或旧邀请码。格式上限 20 GiB、10002 条目；当前备份可能在大库上阻塞写操作，应安排空闲时段。已有备份不会覆盖。
