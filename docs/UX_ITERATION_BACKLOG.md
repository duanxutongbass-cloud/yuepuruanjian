# 后续交互迭代待办

创建：2026-10-09。来源：用户要求全面审查曲谱库交互、合理性与后续版本修改建议。证据唯一记录在 INTERACTION_REVIEW，本文件只维护待办、建议顺序和验收条件。

原 24 项不能整体视为已完成。2026-10-10 用户实测反馈后授权 0.9.6 交互改进，范围见 INTERACTION_FIX_REQUIREMENTS，实际通过证据在对应修复报告；涉及 UX-03/05/12/17/18 的部分改进不等于这些工作包全部完成。保存失败恢复、表单作品保护和实机验证等剩余项仍待实施/验收，不擅自改 Phase 编号或提前进入 NAS/商业版。

## 建议分批

- UX-A：可靠性与防误操作，先做 UX-01～06。建议在把 App 用于正式演出前优先处理；若 Phase 9 复现真实数据丢失/误翻页，应提升为当前验收阻塞，不能仅以“未来优化”掩盖。
- UX-B：任务效率，覆盖找谱、导入、授权、版本、节目单、发布和系统返回的相关 P2。以完整用户任务为单位交付，不只逐页换皮肤。
- UX-C：大 Pad/笔/脚踏与可访问性，以真实设备观察为前提；涉及输入可靠性的 UX-19、UX-22 若真机证实有错误，提前到 UX-A，不因分组拖延。
- 当前 Phase 9 仍需真机/复杂 PDF/长期/规模验收；UX-A/B/C 是后续软件迭代工作包，不是 Phase 10/11 的替代规划。NAS、身份认证与多租户阶段保留原路线。

优先级：P1 = 优先处理作品保护/演出误操作；P2 = 常用流程效率/可理解性；P3 = 使用熟练后的增强。每项均需独立测试、受影响全流程回归与 Phase 9 真机复核；不能仅凭视觉稿关闭。

## UX-A：可靠性与防误操作

### UX-01 P1 保存失败的笔画可恢复

目标：保留按成员/版本/源页/图层隔离的待提交修改，区分保存中/已保存/失败；提供重新提交或明确丢弃。generation 冲突先比较/恢复，不自动覆盖别人的变化。恢复路径只对仍授权的原 scope 可用。

验收：模拟 Room 异常、权限撤销、版本切换和重新打开；失败笔画不伪成功、不写错谱，仍授权时能重试找回，未授权时不能展示/提交到新身份。进程终止的草稿恢复是否持久化需明确方案，不用无限内存承诺保护。

### UX-02 P1 连续书写与保存串行化

目标：同页连写不因逐笔存盘而停止接收；输入预览与队列/已持久化状态分离。翻页、发布和演出入场仍等待安全提交或明确处理失败。

验收：慢保存夹具下连续多笔全部可恢复，提交顺序与最终 generation 正确，无重复/丢笔；后台/跨页/取消/冲突不串页；有队列上限和背压反馈。再用真实笔记录响应，不拿快模拟器掩盖。

### UX-03 P1 锁定整场演出的影响预览

目标：锁定前展示节目顺序、所有涉及版本/谱段、已发布/未发布草稿和空页摘要，以及哪些结构之后不能修改；确认主体明确为整场，不是当前页。提供创建下一场/新方案的路径，保持旧快照不可变。

验收：管理员知道锁定影响后才确认；未发布内容不混入快照；同一场不覆盖/解锁；普通成员无此操作。若建议复制节目单，必须说明共享曲目仍受旧锁约束，不能只复制节目单就声称能改旧 PDF。

### UX-04 P1 未保存表单与过期字段保护

目标：有修改才询问保留草稿/丢弃；无修改直接关闭。过期表单显示受影响记录和字段差异，可保留输入或显式合并后基于最新事务重验，不能换 token 偷写。

验收：点击外部/返回/关闭、配置恢复、目录并发变化、角色变化；不悄悄丢输入、不覆盖新数据、不向新成员显示旧私有目录/草稿。保存状态不明时核验提交结果再重试，避免重复新增。

### UX-05 P1 统一书写/保存/模式/离页门禁

目标：读谱 Fit、刷新、上一/下一页、脚踏、返回、旋转及进入演出采用统一的可执行状态。未完成笔画明确完成或取消，保存等待有反馈和退出路径，不永久禁用返回。

验收：书写中触发 Fit/第二手指操作/旋转/返回；没有无提示半笔丢失、跨页串写或队列误翻页。失败时用户知道哪些已保存、哪些待处理，重试和退出都可用。

### UX-06 P1 明确区分普通阅读/排练/单曲专注/正式演出

目标：节目单详情有明确“准备演出”动作与整场检查，读谱图标不能仅用 Fullscreen 隐喻承载正式入场；单曲专注不伪装成已锁定整场。正式演出退出/返回使用防误触设计，保留清晰安全出口，脚踏默认不容易误切模式。

验收：首次使用者能判断当前模式、何时锁定、退出后落点；检查失败仍停在可修复步骤。快速误触/脚踏误按不无提示结束正式演出；不得给每次普通阅读返回都加阻碍性弹窗。脚踏是否保留默认模式切换待真机与用户确认，不擅自删除既有映射。

## UX-B：任务效率

### UX-07 P2 搜索与筛选

目标：曲库/节目单/管理支持名称检索，作曲者/声部等合理筛选按角色显示；成员名单和下拉选项可搜索，不做无限长菜单。

验收：记录/授权变化及时更新，清筛选、无结果状态可恢复；不通过搜索建议泄露未授权声部或私人批注。先按现有 Domain 可见投影实现，规模查询优化经实际数据评估。

### UX-08 P2 最近、常用与继续阅读

目标：减少“每天重复找同一份谱”；最近/常用与当前演出有明确入口。选择成员、版本和绑定改变时重验，不恢复错误历史。

验收：成员间隔离，归档/撤权/换版清理或明确失效；正确范围内恢复页面，永久阅读历史若新增必须明确本地存储与迁移，不将 SavedStateHandle 冒称持久历史。

### UX-09 P2 当前身份与角色入口

目标：普通页面清楚显示当前演奏员/声部，切换集中且反馈明确；普通成员不以无意义管理页面占主要路径。首次空库显示可执行的管理员创建入口。

验收：切换即清旧数据，不能在另一成员名下操作旧表单/看谱；可访问性焦点合理。隐藏管理入口不代替后端授权，本地身份入口不宣传为生产登录，生产身份依 Phase 10。

### UX-10 P2 错误上下文与可执行修复

目标：Domain/准备错误保留曲目、节目项、声部/页段上下文；普通成员知道联系谁，管理员可定位可管理记录。整场错误摘要可逐项列出，不让一个错误把整场信息变成泛化“重试”。

验收：缺谱/越权/分配歧义/损坏/页段错误可定位且权限安全；正式入场仍严格拒绝任何未修复项目，不静默跳曲/改奏。避免把私人路径、原 URI 或不可见声部泄露给普通成员。

### UX-11 P2 以任务为中心的导入流程

目标：选择真实 PDF→校验/预览实际页数→选择新建/已有曲目及声部/乐章→绑定页段→授权/分配→可选节目单→确认摘要。保留熟练者快速导入，但避免无意重复新建。

验收：取消不留下半成品，或者明确标记未完成并可继续；页段错误就在字段旁解释；成功可直接查看/继续添加同曲另一声部，不能默认扩大授权。SAF 返回/配置恢复/切成员的请求身份保持安全。

### UX-12 P2 有效授权与实际分配的工作区

目标：成员视角和曲目视角均能管理；展示全局授权、单曲额外授权、实际有效访问来源与当前演奏结果；未保存分配与已生效权限明显区分。批量授权/分配有影响预览和事务策略。

验收：取消某一来源不错误标为全无权限；默认不授权；越权分配/缺谱明确解释；批量失败不留下无人知晓的半成功。所有有效结果来自 Domain，不在矩阵 UI 重新写权限规则。

### UX-13 P2 撤权、角色变化与归档的影响处理

目标：高影响操作展示受影响演奏分配/节目单/依赖和修复链接；提供恢复记录路径。低风险可逆勾选用反馈/撤销，避免每个 checkbox 都强制确认。

验收：撤权不静默换谱，最后管理员保护不弱化；归档阻塞明确指出要先处理谁；恢复基于当前事务重验，不能撤销后覆盖新管理员的操作。角色变更、文件/快照仍保留历史边界。

### UX-14 P2 PDF 换版/回滚预览

目标：并列查看当前/候选版本、页数、相关绑定和批注分离提示；显示导入时间/来源摘要/可用性，选择确认再提交。未确认不改变当前版本。

验收：短页数和损坏阻止激活，正确显示旧批注去哪；不默认迁移归一化坐标到不同排版。任何迁移功能需另行方案和人工校验，不以本项批准自动迁移。

### UX-15 P2 节目单编排与状态表达

目标：使用演出者看得懂的一基显示顺序；内部 sortOrder 保留原规则。支持可访问的上下移动，按实际需要增加拖动/批量添加；启用/停用/归档视觉区分，编辑状态与真正检查就绪分开。

验收：重排完整事务保留归档占位/重复曲目独立 itemId；锁定禁止修改；屏幕阅读器可移动而不依赖拖动。日期/场次元数据是否开放由产品确认，不能把 READY 标签当检查成功。

### UX-16 P2 发布范围与结果可见

目标：区分共享草稿、已发布、存在未发布更改；发布动作清楚标明当前页与结果，有差异预览或合理撤回路径。整曲批量发布可作为后续增强，范围显式确认。

验收：用户不能误认为“当前页发布”就是整曲发布；私人层不发布；共享草稿不泄露；新发布不能改变既有冻结快照。减少无差异重复发布生成无意义版本。

### UX-17 P2 批注工作区认知与历史

目标：简化“编辑哪个层/显示哪些层/当前工具”的表达；只读共享层有清晰原因，不用灰图标让人猜。页/图层切换、刷新会改变撤销栈时提供合理状态；评估按页/层保留有限会话历史。

验收：隐藏层不误编辑，管理员排练页与曲库草稿语义明确；颜色/笔宽和工具状态不无提示重置；撤销不能跨版本/成员、不把已发布/锁定历史当可撤销草稿。

### UX-18 P2 擦除/套索/移动预期

目标：对象橡皮明确选中/预览整条将被删除，保持撤销；套索后移动有明确选择/移动反馈。按使用反馈再评估笔划局部擦除、符号大小/选择范围，不假称当前已有。

验收：擦除一小段不会无提示删整笔；套索长线/符号、越页面边界和移动失败可恢复，准确源页坐标不变；后台耗时选择有反馈。

### UX-23 P2 管理返回栈与大屏详情

目标：系统返回和页面返回在单栏详情一致先回列表，保留滚动/筛选/选中；详情不只留巨大标题列，按内容选择信息密度。弹窗主保存/取消动作清晰，数字字段用合适键盘与字段级错误。

验收：系统 Back、预测返回、横竖切换/键盘打开、多标签返回都合理；未保存草稿依 UX-04；1200 dp 以上不按比例放大字体，不改变后端归档/唯一约束。

### UX-24 P2 明确本地就绪、准备与演出进度

目标：节目单详情显示当前成员能否准备的安全摘要，缺文件/未锁定/未分配有定位动作；准备显示当前曲、取消、检查进度，阅读页码不被普通提示替代。可选下一曲提示，正式演出最后一页结束状态明确。

验收：离线仍可读本地，不能把“在线”“已缓存”误当可正式演出；没有下载器时不显示虚假下载入口；提示不遮谱，准备检查不跳过页/授权/冻结图层；检查状态只针对准确的版本和本次入场。

## UX-C：真机输入与可访问性

### UX-19 P1验证/P2实施 笔、手指与手掌

目标：提供明确笔优先/手指书写模式，支持合理的手指导航、取消事件和手掌误触回滚；压力/橡皮端/侧键按实际设备能力渐进支持。

验收：真实支持的 M-Pencil 或其他笔与至少普通/大 Pad 验证，不把系统防误触假设成应用保证；笔抬起/手掌取消/多指不能提交误笔或吞有效笔。没有笔硬件时保持未验收，拒绝静默自动切模式。

### UX-20 P2 阅读空间、控件可达与跳页

目标：正式演出保留页码/必要控制，工具可收起且易找回；允许调整控件位置以适应竖屏高 Pad。增加页段内跳页/乐章索引；可选触控翻页区和缩放要防误触，并与脚踏/书写模式互斥。

验收：实际观看距离下文字清晰，手不离合理区域可操作；左右手/站坐姿测试；不能跳到未授权源页。放大必须相应高质量渲染并共用稳定批注变换，不仅拉伸低清位图，像素预算保持。

### UX-21 P2 可访问性与密度

目标：触控目标至少按 Android 建议 48 dp 设计与实测，密排色块避免扩展点击区重叠；选中工具/图层/颜色有语义与非单一颜色提示。缩放字号、对比度、TalkBack 和键盘/外设导航可用。

验收：实际 bounds/相邻 hitbox 检查，不仅统计图标可见尺寸；TalkBack 能读出状态/执行命令，页/模式变更反馈合理；字体缩放和窄窗不裁切按钮，Canvas 保留有意义的页面描述，批注对象替代导航按需要设计。

### UX-22 P2 脚踏学习与恢复向导

目标：系统配对→选择设备→逐个学习→测试→启用，学习有取消；明确设备名/映射来源。清除/恢复默认/删除配置有合理确认或可撤销，说明影响当前设备而不是全体。

验收：真实设备识别、键冲突、设备重连、多设备同键和错误配置恢复；测试不翻谱，学习取消不覆盖旧映射；长按/断开/保存失败反馈可理解，防抖默认不要求普通演奏员懂毫秒。不得引入尚未授权的 BLE/GATT 或后台自动配对。

## 关闭待办的共同条件

实现前确认详细交互和有风险的数据变化；实现后按修复→重测→再审查。明确失败/取消/无数据/忙/角色变化/配置恢复，并验证新手与熟练者两条路径。维护业务测试、交互测试与真机任务证据，未测不写通过。任何新持久化/历史/草稿表都必须保留升级数据，继续禁止 destructive migration。
