# 单乐团发布与同步接口边界草案

2026-10-10，Phase 10.0 设计输入。不是 OpenAPI 成品、可调用服务或已冻结实现；以 PHASE10_0_REQUIREMENTS 的确认/待定分类为准。联网协议版本与本地 ZIP formatVersion 分开维护。

## 身份与自定义数据

姓名、声部、分类由管理员输入；成员/标准声部/曲目/版本/节目项都用稳定 UUID，名字和编号可编辑但不改变身份。数据库不写死七人；验收可动态生成七名、更多/更少成员以及不同声部的合成样例，生产不预置这些样例。

用户已确认全局曲目流水号至少三位显示，001–999 后继续 1000、1001…，不回绕或按分类/乐器重置。两位分类号独立；接口、导入和文件名解析不得假设曲目号恰好三位，排序按流水号数值。后续测试覆盖 998、999、1000、1001 的生成、排序、导入导出和重号拒绝。

服务认证得到 principal 和 deviceId，服务端校验注册关系和实时角色；请求自报成员或管理员身份不能扩大权限。管理员管理目录与谱文件读取分别鉴权；网络成员端不能继续使用本地任意身份选择器冒充登录。首次接入需显式绑定旧成员 ID，不能按同名自动合并。

## 原件与配送资源

- SourceVersion：原 scorePdfId/versionId/hash/pageCount，不可变；activeVersionId 仍是唯一当前版本来源。
- DeliveryArtifact：独立 artifactId、字节 hash/size、配送 pageCount、sourceVersionId、按序 pageMap、生成工具/版本及发布 revision。下载只提供授权 artifact，不提供母库路径或外部 content URI。
- pageMap：每个配送 PDF 页映射到原版本的源页（原记录零基，UI 显示一基），并核验尺寸/旋转/裁切变换。简单完整页复制可以保持归一化坐标；改变裁切/旋转时必须显式转换和测试，不猜测比例。
- 原版批注仍按原 versionId/sourcePage 归一化坐标关联；页面显示、cache hash 和原版本 hash 不能混用。Android 10.3 需要显式配送模型/适配及必要迁移，不能只把 managedFilePath 换成新下载路径。
- 同一 PDF 跨声部页段，不能因 UI 隐藏其他页就发送整文件。未验证的分谱阻止发布；不采用简单截页后宣称没有隐藏资源/附件泄露的做法。独立声部文件、受审查分谱生成与原页映射必须通过内容及越权测试。
- 源文件 hash 相同不等于有权下载。逐请求校验当前成员、设备、发布版本和资源授权，续传/重试同样校验；不暴露共享文件夹、永久公开链接或绕过鉴权的静态 URL。

## 接口工作清单（路径暂定）

| 接口族 | 边界 |
| --- | --- |
| 会话/注册 | 首次认证、邀请/设备绑定、令牌续期/失效；离线阅读不依赖实时续期。临时失败不清空用户资产 |
| 管理目录 | 成员/声部/分类/全局编号、权限和分配；新增/编辑/归档，最后管理员保护，基线 revision 防过期覆盖 |
| 导入/上传 | 受控暂存、大小/hash/页数校验；幂等请求、失败重试，不自动发布。元数据不得引用尚未完整提交的文件 |
| 发布预览/提交 | 基线 revision 的成员可见清单和配送资源校验；提交原子生效，失败无半发布。批注快照仍不可覆盖 |
| 我的变更 | 根据认证身份生成投影；包含 revision/cursor、授权新增/更新、撤权 tombstone、节目单及映射，不返回全表快照或他人私人数据 |
| 授权下载 | artifact 逐文件鉴权；稳定内容标识供续传及完整性校验。旧 cursor/下载任务必须重验，不因历史 manifest 还在就绕过撤权 |
| 设备确认 | 记录“已提交本地的 revision + 校验成功资源”，不能把发出请求或收到清单算已同步；按设备区分状态 |
| 本人批注备份 | owner 由服务身份确定，scope 对应原版本/源页；CAS 修订、幂等、冲突保留，管理员接口不返回他人个人层 |
| 母库备份/恢复 | 管理员独立授权；复用开放资产语义及格式演进，不把数据库目录复制冒充一致备份。私人灾备另设同意与密钥边界 |

## 客户端提交顺序

获取清单与鉴权 → 校验协议与引用 → 私有暂存下载 → hash/页数/映射校验 → 原子提交 Room 元数据及可用文件引用 → 确认设备同步 → 清理已无授权且无合法引用的文件。失败保留旧的完整可用版本，不把半下载标 CACHED；权限收回不能保留旧权限作为失败回退。

撤权不销毁本人批注。无法再看谱的历史私人笔画仍需有本人取回路径；旧本地 AssetArchiveStore 要求启用成员，与生产账号撤销后的备份能力需在 10.3 分开审查。NAS 账号失效不能成为永久锁死私人资产的机制。

现有原型设备可能已经有完整母库/多个成员文件。新网络投影过滤不会自动清除这些旧字节；接入生产需管理员先做独立备份、确认数据归属及设备隔离迁移，不静默清库，也不声称仅换登录界面便满足文件级隔离。

## 必须实际验证的场景

1. 自定义名字/声部、空字典、修改名字、人数变化不改变 UUID/授权，不能使用七人硬编码。
2. 混合母 PDF 经授权分谱后仅配送合法页面/内容；sourcePage、坐标和旧批注不串页，原件/配送 hash 不混用。
3. 默认声部不自动授权、单曲例外不扩大全局、实际分配不扩权；多来源撤回、替补到期和管理员身份分别测试。
4. 猜 artifact/他人 memberId、续传、旧清单、令牌/设备撤销、跨账号残留缓存不能绕过服务端下载权限。
5. 发布中断、重复提交、metadata revision 变化不半发布；设备确认失败不能误记已同步。
6. 换版/回滚、冻结节目单、演出中更新保持历史，异常明确停止/重验，不静默读另一份谱。
7. 离线编辑/重装/换机、旧基线写冲突、重复请求、撤权后本人取回不静默丢笔画或读他人层。
8. NAS 停服、数据库与文件一致恢复、开放格式取回及私人恢复权限分别验证；备份文件还在不等于恢复演练成功。
