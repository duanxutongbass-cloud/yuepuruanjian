# Phase 7 审查

日期：2026-10-09。结论：Phase 7 的本地正式演出、整场准备检查和离线可靠性软件范围通过。不是物理 Pad、无线脚踏、复杂 PDF 长时间性能或联网商业版验收。未启动 Phase 8。

## 范围与交付

在现有工程上继续，APK 0.7.0 / versionCode 5，minSdk 26。数据库仍为版本 3，既有 1→2→3 迁移和 schema 不变；sources/ 未修改，未引入新依赖或蓝牙协议库。

- PerformancePreparation 只接收 Domain 已解析的个人节目单及精确声部/页段，不自行授权、选择声部或排序。
- 进入正式演出前检查所有曲目的本地文件、SHA-256、准确版本、actual pageCount 和授权页段。Native PdfRenderer 逐一打开页段内每个源页，资源逐页关闭，不预先分配全场位图。
- 每个授权源页通过 AnnotationStore 重新校验当前成员、谱身份及个人/共享批注；正式节目单演出要求既有共享快照已锁定且 manifest 有效。管理员未锁定时明确拒绝进入正式演出，普通阅读及跨曲排练仍可使用。
- 单曲专注阅读不要求节目单快照，但仍检查该曲文件与批注。不把当前系统 HID 软件能力或本地成员选择宣传为生产身份认证。
- 检查显示进度、支持取消；检查期间触屏和脚踏不排队翻页。失败给出明确状态，不跳曲、不换版本、不扩大授权。
- 正式演出常亮、隐藏编辑栏，强制展示个人及冻结共享层，不渲染管理员草稿。退出/离开阅读后恢复屏幕常亮标志；演出及准备时禁用刷新入口，避免误刷新打断。
- SavedStateHandle 只保存准确身份下的游标与演出意图。重建后先重新检查，不能凭旧布尔值直接重新宣称就绪。
- 离线标识采用固定高度，本地 PDF 和 Room 不依赖网络。仍逐次校验实际打开的文件；入场后文件丢失/损坏或批注读取失败退出正式演出并明确报错，不能把检查结果当作永不失效的缓存。
- 检查上限 10,000 个授权页，过程可取消。没有新增下载器、NAS/GATT、多租户、永久阅读历史或全场位图缓存。

## 修复与复核

1. 准备 UI 会改变视口大小，原生渲染可能与准备检查互相等待。检查持有既有原生互斥锁，释放后等待当前 Ready/Failure，再验证 epoch、节目身份和 pending 变化，防止检查完成时错误进入演出或永久停在 Checking。
2. 所有成员/清单变化、取消和 detach 都取消准备任务并推进 epoch，旧结果不得进入新成员的演出。配置恢复重新检查；缺失第五曲即使当前第一页可读，也不会进入正式演出。
3. 冻结共享快照读取原来仍依赖后续可变的 publishedRevisionId；现在读取快照不查实时发布指针。新增测试模拟实时指针错误：冻结演出仍读取原快照，普通未冻结阅读仍拒绝错误实时记录。
4. 准备检查通过不代表当前 UI 中排练批注缓存已更新。入场及演出页绑定刷新当前页批注；加载期间不显示旧图层，正式节目单仅在当前页已加载正确锁定数据后展示。新增真实 Room/Compose 测试从缓存红色排练批注转到蓝色冻结批注，确认读取新快照而非旧缓存。
5. 演出运行期原生错误清除演出状态及保存意图；运行期批注错误同样退出正式演出。保持显式错误与重试，不自动跳曲。
6. 初轮常亮断言早于 Compose 副作用落地，修正测试等待原生页就绪及 UI 空闲后断言实际 View 树中的常亮属性。未删除断言，也未只检查 ViewModel 布尔值代替 UI。
7. 原生检查从只打开每段第一页加强为打开所有允许源页；页码仍以一基闭区间绑定、零基渲染索引转换，返回尺寸列表保持既有 API 兼容。

- Android 14/API 34 AOSP 模拟器 20 个测试全部通过，失败 0、跳过 0；原 18 个回归按正式演出锁定要求增强，新增入场拒绝未锁定/缺失末曲及入场刷新冻结批注两个真实页面测试。
- APK 0.7.0 构建成功；Lint 0 错误、11 个非阻塞警告和 1 个提示，与上一阶段同类固定依赖更新/KTX/Compose 提示。没有关闭检查或新增 baseline。
- 既有 Room 数据保留迁移、权限拒绝、页段/版本解析、导入回滚、批注持久化/发布/快照与导航测试继续通过。

五曲 Android 用例使用真实 MainActivity/Hilt、Room、Domain、Native PdfRenderer 和 Activity KeyEvent，管理员先建立整场冻结快照，成员仍按实际 Violin I/II 分配读取 2–3 或 3–4 源页。测试关闭模拟器 Wi-Fi/移动数据，并等待真实 UiState.offline 为 true；完成十页顺序演出、首尾边界及反向跨曲。准备状态实际为 Ready(10)，UI 常亮；1280×1800 重建后重新准备并恢复第四曲/原源页，返回后实际 View 常亮解除、普通导航恢复。

另一个真实用例先拒绝未锁定正式入场，普通第一页仍可读；管理员锁定后删除第五曲测试 PDF，再次入场会在当前第一曲明确报“第五曲文件缺失”，不进入正式演出，也不靠先翻到第五曲才发现。冻结批注刷新用例确认正式入场展示后来锁定的蓝色记录而不是缓存红色排练记录。

JVM 另覆盖所有十个源页检查、后页批注损坏、取消后不补执行按键、旧准备结果成员隔离、恢复时重新发现缺谱、准备后运行期文件丢失、超页数上限及冻结快照不依赖实时发布指针。

本次构建曾跨越会话/执行暂停，构建输出的累计耗时不是连续演出或压力测试证据。

## 边界

没有发现阻塞本批次软件范围通过的遗留问题。准备检查不保证文件以后不会被删或篡改，因此运行期保护不能移除；全文件 hash/打开源页也不等于所有复杂字体/图像渲染都已实机验收。

当前全表事务快照和逐页批注检查仍需大数据量评估。未实现额外的全场位图预加载，保持受控视口内存；10,000 页上限不表示已完成 10,000 页性能验收。实际 Pad 常亮与厂商省电策略、无线断连/延迟、长时温度/内存/复杂 PDF、进程强杀和低存储条件仍归 Phase 9 实机验收。永久阅读历史、导入孤儿文件清扫、完整管理、NAS、生产登录和商业版没有被本阶段隐式宣称完成。

允许进入 Phase 8 管理端完整化，但本次未启动 Phase 8。
