## 实现

- `AnnotationState` 分离 busy（读取/计算）、saving（串行写入）与 pending（未确认内容）；已完成笔画立即进入内存工作副本，数据库确认不会用旧快照覆盖后来落笔。
- 队列保留当前待确认快照与最新累计快照，连续输入合并到第二份，保存按 generation 顺序进行。失败保持工作副本、历史和原基线，显式重试实际写入；失败后继续落笔只改内存，不隐式重试。撤销/重做同样串行处理。
- Repository 仍使用原 Domain 授权和 Room 事务。仅在当前 generation 恰为基线+1 且规范化 payload 完全相同时确认重复提交；鉴权和角色检查先执行。其他版本/内容冲突保留本地候选，不重设基线覆盖数据库；界面可确认放弃并重读。
- 切页、Fit/缩放、重开、入场、脚踏、发布、冻结使用 transitionBlocked。普通离页没有额外弹窗；有未完成操作时提供留下处理或明确“仅保留在内存并离开”。强制身份/授权投影变化停止旧任务，按完整 scope 隔离草稿，迟到回调和旧手势 token 不更新新会话。
- 回到原 scope 先重新读取授权；恢复草稿仍等待显式重试。角色降级不展示原共享草稿；撤权后保留待处理内容但不显示/提交至其他身份。可解除编辑锁与不可变演出冻结均保留，未改写 Domain。
- 手势跨首笔保存失败时 editable 保持可接收本地输入，避免 pointerInput 因错误重组而取消第二笔。画布变化、多指介入、事件被消费或单笔上限取消未完成笔画时有明确提示；旧 scope/token 回调不能串写。

## 恢复与容量边界

仅同一个 ViewModel/进程的内存恢复，不是持久 outbox，强杀、进程回收、重启及清数据会丢失未提交内容，界面明确说明。配置变化中 ViewModel 可保留已完成草稿，未完成手势按取消提示处理。最多暂存 16 个离页草稿，不静默淘汰；单页 2,000 笔/100,000 点、单手势 4,096 点，达到上限明确拒绝/取消；每个撤销/重做历史栈最多 20 步/400,000 点。队列两份快照使用有限内存，仍需真机规模与笔输入性能测试。

强制换版或撤权后的历史草稿不会自动迁移到新版本或其他成员；原版本/权限无法恢复时，本批没有独立导出待处理草稿的入口。永久冲突须保留在当前进程处理或显式放弃，不能宣称所有失败均可自动恢复。

## R2 独立复审发现：恢复鉴权窗口

R1 审核后发现：恢复内存草稿时把旧 data 放回公开 StateFlow，仅设置 busy；普通阅读仍绘制该数据，导致慢鉴权期间短暂显示历史私人/共享笔画。普通刷新也保留旧 data，存在同类窗口。新增 4 项延迟 load 回归在修复前全部失败，证据为 auth-window-reproduction.log 和 auth-window-before-fix/ 下 XML；R1 包不再作为可接受候选。

R2 在 bind 恢复时立即将公开 data 清空，同时清空选择和历史可用标记；普通刷新也先清空 data。原待提交内容与 undo/redo 仍保存在私有内存队列/栈，不通过公开状态泄露。仅当前 epoch/scope 的 repository.load 成功后，才基于重新取得的权限恢复获准图层；拒绝及再次慢重试都保持隐藏。角色降级不恢复共享草稿，重新取得管理员权限后才可恢复并显式重试。Reader 在 data 为空时不创建 AnnotationOverlay；busy 不再被当作鉴权显示边界。
