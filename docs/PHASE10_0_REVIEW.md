## 实际盘点与纠正

- 用户明确“没有工具”，因此废止当前规划中“复用既有 Windows 工具”作为必然前提；10.1 新建工具。没有已提供 GitHub 仓库，不再要求用户寻找不存在的半成品。
- sources/ 本次目录枚举没有文件；tools/ 仅有 Android 诊断和归档校验工具，没有 Windows 曲谱管理实现。应用项目列表中的通用项目不是已核实的管理工具，不深入扫描或改动无关曲谱文件。
- 用户明确名字/声部应自由添加。读取 DatabaseModule、LibraryEntities、LibraryManagement、ScoreResolver，确认现有 Android 是动态记录、没有生产初始化名单，不把测试夹具当七人固定配置。
- 用户明确需要外网同步；NAS 型号/DSM/内存/套件/备份与实际外网入口仍未实测。不读取密码、连接 NAS、升级系统或开放端口。
- 当前 Android Manifest 不含 INTERNET，仓库没有 HTTP 同步客户端、认证或 NAS 服务；网络状态读取不是联网功能。

## 发现的问题已在设计边界修正

1. 普通成员若收到母库 ZIP/全表快照会带入未授权内容：同步必须生成认证身份的最小投影，母库备份仅管理员独立权限。
2. 混合声部 PDF 只过滤可见页不足以隔离字节：要求授权配送分谱和逐文件鉴权，未验证的资源阻止发布。
3. 分谱与原件 hash/页数不同，直接沿用原版文件路径会失败或错页：原版本与 DeliveryArtifact 分离，明确 pageMap 和批注原坐标；后续要真实实现/迁移测试，不冒称当前 reader 已兼容。
4. 旧原型设备可能有母库及多账号文件，新的过滤清单不自动解决残留：接入生产必须显式备份、归属核对和隔离迁移，不能静默删用户数据。
5. NAS 撤权/账号归档与本人批注取回不能混为一项权限：后续单独设计个人取回能力；不能宣传现有本地成员选择是生产认证。

详细确认/草案分类见 PHASE10_0_REQUIREMENTS；接口和验收输入见 TEAM_SYNC_CONTRACT。问题在设计中已有处理方向，但文件分谱、真实鉴权、冲突处理等尚未开发，不能当作漏洞已被实现修复。

查阅 [DS720+ 官方规格](https://global.download.synology.com/download/Document/Hardware/ProductSpec/DiskStation/20-year/DS720%2B/enu/Product_Spec_DS720%2B_enu.pdf)：原厂规格为 J4125 / x86-64、2 GB 内存。仅是型号资料，不代表用户当前机器内存、DSM、可用资源或套件，也不据此承诺吞吐量。
