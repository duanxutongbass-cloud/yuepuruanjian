## 使用

1. 在 App 内覆盖更新，先联网同步一次；保留原账号、本机批注和缓存，不卸载清数据。
2. 管理员先在曲库发布需要给成员看的共享批注，再进入“管理节目单／整曲选曲”→“冻结本场”→确认。冻结不增加 PDF 权限；管理员自己需要阅读时仍使用“接收阅读”，多声部账号使用“我的阅读声部”选择实际阅读声部。
3. 成员完成本场完整同步后，从节目单打开演出谱并进行演出准备。缺页、缺失/损坏快照或未冻结时不进入正式场次；离线核验仍最长 7 天，到期需联网。读取普通曲库不会延长核验期限。
4. 冻结后需改节目顺序、曲目、名称、可见成员或采用新的共享批注/分谱时，点“复制为新场次”编辑保存并重新冻结；旧场次内容保留。删除/恢复仍使用回收站。退出、后台或进程终止后须重新准备，旧游标不能直接恢复正式入场。

## 服务端已实现

管理员 POST `/v1/admin/program-freezes`，body 为 `programId`、固定幂等 `requestId`、`expectedRevision`。同一数据库写事务检查节目单版本与可用曲目、捕获全场独立 artifactId/hash/页数及**已发布共享批注**，不读取个人层或共享草稿。节目单只冻结一次；同请求丢失回执后可重试，另一个请求不能重写已冻结内容。冻结后编辑曲目、顺序、名称、可见成员须新建节目单，原节目单仍可归档/恢复，原 PDF 和编号保留。

记录共用原 NAS 账号数据库，新增 program_freezes/program_freeze_requests，不删除或覆盖原表。冻结总页数上限 10000、内容上限 32 MiB；失败整事务回退。快照带哈希，已发布共享层后续变化、新声部补传或请求重开均不修改原快照。

认证 GET `/v1/program-freezes/{programId}/{freezeId}` 每次核验账号/设备、节目单可见性、未归档状态及**当前逐分谱授权**；管理员也需相应 PDF 授权。只下发原冻结清单与当前授权的交集，新授予但未参加原冻结的 PDF 不混入本场；个人批注始终由个人账号层单独读取。响应为 protocolVersion/programId/freezeId/sha256/payload，payload 是哈希对应的原始 UTF-8 JSON 字符串。只有当前授权的共享页面会出现在响应中；读取有审计。

曲库清单里的冻结节目单额外携带 freezeId 和 frozenArtifactIds，仅包含当前授权原分谱。成员没有任何可读原分谱时不下发本场。冻结不是新的乐谱授权，知道快照 UUID 也不能访问。普通未冻结节目单协议不变，旧 App 可忽略新增字段；完整演出准备仍需升级后的客户端。

本机服务专项首轮 **11 项通过，73.216s**（7 冻结 + 4 既有节目单）：真实 PDF、已发布/草稿/个人层隔离、后续共享发布和同号补传不改历史、设备撤销、幂等/并发唯一赢家、大小上限回退、真实 HTTP、重启与完整备份恢复。补充有 PDF 授权但不在节目单可见成员中的拒绝及源版本变动拒绝后，**8 项冻结测试复测全部通过，92.477s**。日志 work/team-service-0107-freezes-tests.log、team-service-0107-freezes-retest.log。
