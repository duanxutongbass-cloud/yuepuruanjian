# 全流程交互审查

日期：2026-10-09。基线：现有 APK 0.8.0 / Phase 1–8 软件实现；Phase 9 仍进行中、未通过。

用户本次要求是审查合理性并提出后续版本修改建议，不是立即开发。本次只维护审查与迭代文档，不修改应用代码/APK，不把建议写成已经生效的产品规范。后续需求唯一维护于 UX_ITERATION_BACKLOG。

## 结论

底层业务保护整体合理，但当前更接近功能验证工具，还不能称为经过完整人机体验验收的演出产品。已有权限、版本、页段和快照测试证明了一些业务不变量，不等于找谱高效、批注连写顺畅、误操作可恢复或大 Pad 操作合适。

最高优先级是保存失败笔画的恢复、逐笔保存期间的输入处理、锁定后果说明、编辑丢弃/过期恢复，以及读谱切换与批注手势的统一门禁。其余主要是工作流与可发现性问题。已通过阶段报告保留当时范围，不据此宣称本轮 UX 无问题；这些新发现尚未修复。

## 方法与限制

- 阅读实际导航、页面、管理写入、阅读/批注/脚踏 ViewModel 和相关既有测试；沿首次进入→导入→授权→找谱→批注→节目单→准备→演出→恢复链路审查。
- 复核既有 `annotation-standard-pad.png` 和 `performance-large-pad.png` 模拟器截图；此前管理截图作为已知证据。不是本轮新生成截图，不把局部工具截图当全部页面覆盖。
- 本轮没有重新运行 Gradle、模拟器或用户真机测试，因为未改实现。131 个软件测试是此前实际回归基线，不是本轮新执行的可用性实验。
- 华为 MatePad Pro 2021 / 用户报告 HarmonyOS 4.2.0.213 尚未建立授权 ADB；没有观察真实笔、握持、脚踏、观看距离、屏幕密度和长期排练行为。相关体验只能列为待验证。
- “确定”表示源码/既有测试能证明现状；“推断”表示由事件链推导风险，仍需复现；“建议”表示产品能力缺口，不冒充代码错误。优先级是 UX 迭代顺序，不与线上故障等级混用。

审查采用状态可见、贴近使用者任务、用户控制/恢复、防误操作和减少记忆负担的原则。[NN/g 可用性启发式](https://www.nngroup.com/articles/ten-usability-heuristics/)。触控目标和语义参考 [Compose 可访问性默认行为](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)；笔/手掌取消事件参考 [Android 笔输入说明](https://developer.android.com/develop/ui/views/touch-and-input/stylus-input/advanced-stylus-features)。这些是审查依据，不意味着项目已满足全部标准。

## 优先发现

### P1：批注保存失败没有笔画恢复入口（UX-01）

确定。AnnotationViewModel.edit 仅在 repository.save 成功后更新 data；失败只写 error。retry 清空撤销栈并重新 load，没有保留失败 updated 的待保存队列。既有 `AnnotationViewModelTest.failureDoesNotPretendToSaveAndRetryClearsStaleHistory` 明确断言失败后 marks 为空。

场景：用户写下一笔，保存失败；点击“刷新批注/重试”后看到旧数据，刚写的内容不能重新提交。系统没有伪称保存成功，这是正确的，但“不伪称成功”不等于“用户作品可恢复”。需保留未提交笔画，明确保存状态和重试/丢弃，成员/版本失效时不能把它写到别人的新谱。

依据：`annotation/AnnotationViewModel.kt:122`、`:125`、`:138`、`:46`；`src/test/.../AnnotationViewModelTest.kt:63`。这是待修复发现，不是已修复结果。

### P1：逐笔保存暂停编辑，连写存在输入空窗（UX-02）

确定门禁、真实影响待测。每次 edit 置 busy，editable 要求 !busy；AnnotationOverlay 在 !editable 时不接收书写，stroke 也会拒绝。快写下一笔时若保存仍未完成，界面没有排队接受该笔。源码证实暂停，但未测物理笔的延迟/发生率，不能声称特定设备必然吞笔。

需把“允许继续书写”与“禁止跨页切换/发布”分开，以同 scope 串行提交和可见待保存队列解决；不能移除 generation 冲突检查或并发乱写 Room。

依据：`annotation/AnnotationViewModel.kt:26`、`:93`、`:122`；`annotation/AnnotationControls.kt:111`。

### P1：锁定演出的确认说明小于实际影响（UX-03）

确定。弹窗只说明共享批注不跟随更新，而 LibraryManagement 同时禁止锁定节目项排序、曲目/乐章/声部/绑定和相关 PDF 版本修改；没有解锁/覆盖入口。管理员可能为“固定批注”点击锁定，之后才发现需要新建曲目/节目单才能改谱。

应在锁定前展示整场影响、未发布草稿/空页提示、参与版本摘要，以及准备新演出的路径。绝不能用删除快照或解锁旧快照来掩盖历史语义。

依据：`annotation/AnnotationControls.kt:69`；`data/LibraryManagement.kt:52`、`:55`、`:94`；`annotation/AnnotationRepository.kt:100`。

### P1：表单丢弃与过期处理缺少用户作品保护（UX-04）

确定。ManagementEditor 在不 busy 时 onDismissRequest 直接 close，没有 dirty 判断。目录任意相关变更后 token 失效，保存被禁用，提示关闭后重新编辑；没有保留/对比/复制已输入字段的恢复路径。快照防覆盖是正确的，但现在把重新输入成本交给管理员。

应对确实修改过的表单提供保留草稿/丢弃，旧表单提供与最新记录比较；没有改动时直接关闭，避免每次点击都弹确认。不能把旧 token 替换成新 token 强行覆盖。

依据：`ui/ManagementDialogs.kt:80`、`:103`、`:134`；`ui/ManagementViewModel.kt:32`；`ui/ManagementConsole.kt:137`。

### P1：布局/模式切换与书写手势保护不统一（UX-05）

确定门禁差异，丢笔影响为推断。翻页/演出按钮和脚踏检查 busy/gestureActive，但 Fit 按钮仅检查 preparing；重新打开仅检查准备/演出，顶部刷新也未检查批注手势。Fit/刷新/返回造成画布重建时，AnnotationOverlay 的 pointerInput 以 transform 为 key，未完成 trail 可能被取消。

需通过统一操作门禁处理模式变化、旋转、离页、刷新、跨曲和笔画完成/取消。系统返回不应无限封锁；应有完成保存后离开或明确安全退出。复现覆盖多指、旋转和保存失败后离开，才能确定影响范围。

依据：`pdf/PdfReaderScreen.kt:89`、`:112`、`:118`；`ui/LibraryNavigation.kt:115`；`annotation/AnnotationControls.kt:111`。

## 其他明确依据

- 找谱与角色入口：`ui/LibraryNavigation.kt:122`、`:238`、`:244`、`:250`、`:279`。普通成员仍有“管理”根入口，但后端拒绝读取目录；这是入口噪声，不是在此发现权限泄漏。本地可选择管理员是既定测试身份边界，生产身份必须在 Phase 10 解决，不伪装成隐藏按钮即可安全。
- 节目错误：ScoreResolver.resolveConcert 对全场严格解析，错误附 contextId；LibraryViewModel 把它压成 UiState.Error(code)，页面不能定位具体曲/声部。保留严格“不能带病入场”，可以增加安全的错误摘要和管理员修复链接，不跳过错误曲目。（`domain/ScoreResolver.kt:177`、`ui/LibraryViewModel.kt:44`、`:47`、`ui/LibraryNavigation.kt:186`）
- 页码与模式：`pdf/PdfReaderScreen.kt:97` 通知替代页码，`:122` 使用 Fullscreen 表示实际有准备/冻结语义的演出动作；截图证实顶部多行控制保留，不是完全无控制全屏。不要直接删除安全退出按钮来扩大谱面。
- 批注工具：`annotation/AnnotationControls.kt:53` 至颜色/笔宽行，水平滚动使部分参数在普通窗口首屏外；每次 bind/layer 重置阅读工具/撤销栈是当前真实行为，不能把“刷新”当不会改变历史。（`annotation/AnnotationViewModel.kt:41`、`:46`、`:76`）
- 输入：AnnotationOverlay 使用首个 pointer，未按 PointerType 明确区分笔/手指，没有应用层手掌取消回滚设计；不等于操作系统完全没有防误触，具体笔/设备行为待真机。（`annotation/AnnotationControls.kt:114`、`:122`）
- 颜色控件 visible size 为 40 dp，Compose 可能扩展点击区域，不能仅凭源码断言可点面积一定小于 48 dp；密排扩展区重叠/误点与语义选中状态需测。（`annotation/AnnotationControls.kt:87`）
- 管理：`ui/ManagementConsole.kt:188` 分配选择以整个 token 为 rememberSaveable key，其他目录变化可重置未保存候选；授权即时提交与分配另点保存应有清晰区分。排序/批量操作和过期恢复必须保留事务和唯一约束，不在 UI 手改权威规则。
- 脚踏：`core/pedal/PedalSettingsScreen.kt:63`、`:67`、`:76`、`:77` 直接学习/清除/重置/删除；`PedalViewModel.kt:65` 没有单独取消学习 API。退出页面/切测试能结束学习，不是永远锁住用户，但发现成本高。

## 保留的好设计

不重写 Domain，不以管理员身份绕过谱权限；保持 activeVersionId 单一来源、一基绑定和旧版本批注隔离；快照不可变、断网不放松授权；失败明确停读而非自动跳曲；防重复脚踏与编辑期间不积累翻页；归档保留数据；过期表单防覆盖。后续 UX 应改善这些规则的表达与操作路径，而非取消规则。

本轮未证明整套产品没有其他交互问题；尤其键盘遮挡、字体缩放、屏幕阅读器、笔/手掌、双指输入、物理高屏可达性和真实排练时效需要 Phase 9 设备任务验证。后续版本与验收任务见 UX_ITERATION_BACKLOG。
