## 用户最终规则

个人批注按账号分别存储，同账号多设备同步，普通成员互相不可见。用户随后明确管理员应能读取已上传个批，因此提供独立的本团队管理员只读入口；目标账号已确认 NAS 备份说明，并且管理员具有对应乐谱权限，逐请求鉴权并审计。没有修改他人个人笔迹接口。管理员面向全体的批注使用共享草稿，显式发布后才对获授权成员显示。个人层不自动变成共享层。

## 使用

“我的 → 团队账号与设备”可查看批注同步状态、重试、处理冲突和“取回我的批注备份”。管理员在同页选择成员、自己已获授权的分谱及页码，读取已上传笔迹并叠加本机谱面，只读；本机缺谱时提示并显示笔迹预览。授权撤销或退出账号后隐藏预览。共享层在曲谱批注工具栏编辑并发布当前页。

笔迹先保存到当前账号独立 Room 库，再在应用运行时合并短时间触发上传；首次、返回前台、前台每 60 秒或手动同步会刷新。没有新增 OS 后台任务。书写模式下延后用云端笔迹替换当前页，上传仍可进行；切回阅读或离开页后刷新，PDF 渲染不因同步清空。

## 数据与冲突

按独立 artifactId、不可变 hash、源页、个人账号或 shared 层定位，不按名称、编号或时间匹配笔迹。个人、共享草稿、已发布三层分别使用服务端修订号。稳定 requestId 和请求正文在本机持久化后发送；确认丢失重试原请求，不能重复生成一份提交。服务端以认证账号决定 owner，鉴权先于幂等查询。

旧基线提交返回 409，服务端持久保存候选与结果，App 保留本机笔迹并显示双方位置预览。用户必须显式比较、再次确认选择；不自动合并或按时钟覆盖。选择前核对本机 generation 及云端修订，期间再次变化继续拒绝并提示。原笔迹保存到历史记录；已冻结演出快照及原 PDF 保持不变。共享发布也校验草稿与发布修订，不能绕过草稿冲突。

新增 annotation_cloud 只保存传输基线、待提交请求及冲突，不保存令牌或密码。schema 5→6 增加新表，不破坏旧批注/发布/冻结记录；所有旧迁移链已补注册。既有开放资产格式 3 / databaseVersion 5 的逻辑表不变，不导出账号传输队列。新增个人 JSON 取回格式 team-personal-ink v1，包括本人云端当前记录和本机已保存个人候选，不含 PDF 或他人批注；它是开放取回文件，当前没有新增 JSON 一键恢复入口。

撤销 PDF 权限不删除个人笔迹；本人账号仍可取回本人云端备份，本机已保存的历史谱页笔迹也随取回导出。退出/切换账号使迟到回调失效，不把旧队列写入新账号。账号本身已停用/失效仍需恢复合法账号后取回，不提供免认证绕过。服务端单页最多 2000 笔、100000 点，单页 JSON 8 MiB，单次清单最多 10000 条；个人取回合计 32 MiB，超限明确报错。

## API 与运维

- GET /v1/annotations：当前账号有谱权限的批注清单；个人层只返回本人，共享草稿限管理员。
- GET/POST /v1/annotations/{artifact}/{page}/{personal|draft|published}：零起始源页；POST 携带 protocolVersion=1、requestId、baseRevision、artifactHash、marks；发布另带 draftRevision。
- GET /v1/annotation-backups 及 /{artifact}/{page}：本人已上传个人层，PDF 撤权后仍可访问，不包含 PDF。
- POST /v1/admin/annotation-backups：accountId、artifactId、pageIndex；只读、目标已确认说明、管理员有谱权限，并记审计。
